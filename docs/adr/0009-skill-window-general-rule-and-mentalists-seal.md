# 技能窗开窗总则：rank 被任何伤害新亮出即开窗，感应者是唯一绝对封印者

旧共识是"只有攻击/挡刀伤害新亮出 rank 才开技能窗，技能伤害与反伤不开"（耦合点 A3，语料 `skill.reveal-rank` 旧表述、帮助文案、引擎 `_after_damage` 三方一致）。产品方裁定（2026-10-03 规则共识访谈，**自定义规则、部分推翻旧表述**）：开窗总则改为——**rank 被任何伤害（攻击/挡刀/技能/反伤，自选或被迫）新亮出即开技能窗，唯一例外是感应者（rank 5）的强制亮出**。被感应者点出等级 = 该玩家技能**绝对永久封印**，炼金治疗退回 rank 亦不可解（"炼金解封"不存在）。

封印实现采**方案 A**：感应者强制亮出受害者 rank 时，直接把该 rank 写入现有 `skills_used`——与"已使用/已弃用"（ADR 0008）共用同一把永不清除的资格熄灭锁，不加新状态位、不加新事件类型。产品方知情并接受代价：对局状态上区分不了"用过"与"被封"，审计需翻事件历史，玩家侧靠规则说明而非独立事件传达封印。

## Considered Options

- **保持旧总则（技能伤害/反伤亮 rank 不开窗）**：改动为零；被否决——产品方选择更激进的一致性："亮 rank 就该有技能窗"一句话讲完，队友刺客打→受害者自亮 rank→立刻用技能成为合法连招。
- **封印可被炼金解除**：被否决——用户原话「炼金治疗之后回退 rank 之后也不能重新开技能」「感应者的封印，炼金能不能解？不能」；感应者的战略定位就是不可逆的点杀。
- **独立封印状态位/新事件**：语义更干净；被否决——方案 A 改动最小（约 2 行 + 分支测试），且"用过=被封"在玩家侧效果本就相同。

## Consequences

- 连带反转：狂战反伤打出第 3 点被迫亮 rank → 开窗（`rule-conflicts-from-chinese-manual.md` 第 7 条由"文档矛盾"销案为正确）；刺客/炼金 harm 逼迫受害者自亮 rank → 开窗（与 ADR 0006 组合成连招）。
- 审判者连带（D1 推论，随总则自动成立）：被非感应者伤害亮出 fleur-cross → 诅咒窗照样开；**被感应者封印 = 诅咒胜路当场永久作废**——感应者成为定位 + 废诅咒双料克星。
- "技能伤害不触发干涉投票"维持不变（语料明文，未在本次推翻范围）。
- 引擎改动量最大的一条：`_after_damage` 开窗条件重写、感应者写 `skills_used`、连击中途开窗后的匕首移交时序（`state.pending is None` 条件须覆盖新场景，即耦合点 B12）；ruleset bump（0.4 → 0.5）、分支测试、golden、coverage、帮助文案（A3 旧表述改写）同步。
