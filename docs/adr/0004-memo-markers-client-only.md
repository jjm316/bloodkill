# 备忘标记为纯客户端本地状态

玩家需要对局中私下记笔记（猜测各玩家的阵营与等级）。决定：备忘标记完全是前端本地状态——只存在玩家自己设备的 localStorage（按房间码 + gameId 维度，检测到新对局自动清空），不进 WebSocket 协议、不进引擎、不进任何投影或事件。理由：备忘的本质是"玩家的猜测"，天然属于客户端；服务端零改动意味着协议与规则版本不动、存档兼容不受影响；私密性由"根本不上传"保证，比投影过滤更省心。代价是各设备不同步、清除浏览器数据即丢——对局中的临时笔记可接受。

## Considered Options

- **服务端存储并随投影下发**：可多端同步，被否决——协议、引擎、存档全要动，还要为"每人只看得到自己的标记"加投影过滤，为一个纯便签功能不成比例。
- **纯内存（刷新即丢）**：最简单，被否决——手机端切后台/锁屏就可能丢，体验差；localStorage 已有先例（`bloodbound:*`），成本为零。

## Consequences

- 前端任何命令 payload 都不得携带备忘标记；回放页（ReplayScreen 复用 Board）不显示备忘角标，回放是公开复盘视图。
- 同一玩家多设备（手机+电脑）各记各的；界面文案注明"仅保存在本设备"。
- 界面必须把备忘角标（私有猜测）与三格线索槽（公开亮牌事实）在视觉上区分，避免误读为对局事实。
