# 亮牌/技能/退牌单人窗口加超时兜底

干涉投票自 2026-09-04 重构起就有完整超时（房主配置 30–180 秒；投票阶段到期视为不干涉、目标三选一阶段到期视为全部拒绝），但同为单人决策窗口的亮牌窗、技能窗、退牌窗没有任何超时——玩家断线即全场永久停摆，只能干等重连。本项目的部署形态是"手机朋友只开 URL"，远程玩家掉线挂死全局是最差体验。产品方裁定（2026-10-03 规则共识访谈）：三类单人窗口全部加超时兜底。

到期语义（L4 细化）：**全程自动执行确定性默认，不用房主代行**——亮牌窗自动亮排序第一张（marker-0 → marker-1 → rank）、wild 色选窗取问号、技能窗视为放弃（即弃用，按 ADR 0008 构成永久失去）、退牌窗自动退排序第一张（marker 先于 rank，保住"亮槽数 = 伤害数"不变量）。配置：房主开局单项"单人窗口超时"，三类窗口共用，预设 30/60/90/120/180 秒、**默认 90 秒**。

## Considered Options

- **不加超时，维持断线挂起**：适合全员面桌、社交压力自治的场景；被否决——远程玩家体验不可接受。
- **房主代行（到期由房主替玩家选）**：被否决——房主替别人做战略决策责任过重，天然带作弊嫌疑与背锅风险。
- **技能窗到期关窗但不记弃用**：对断线者温和（干净记录者仍可走"治疗退 rank → 重亮首次开窗"路）；被否决——留下"故意拖满时限免承诺"的漏洞，且与"窗口只有一次、放弃即失去"的一句话规则冲突。

## Consequences

- 服务端按既有模式扩展：DeadlineScheduler 为三类窗口代发 timeout 命令，deadline 由 Room 持有、引擎不存墙钟（重放确定性约束）。所有自动默认走确定序（marker-0 → marker-1 → rank），杜绝 ADR 0006 前自动亮牌的迭代序不确定性。
- wild 色选窗默认问号的前提是色选窗含问号选项（玫/兽/？三选，同批裁决）；该选项的实现已在产品方另一工作单推进，两边须对齐。
- ruleset 随本批共识 bump（0.4 → 0.5）；超时分支测试、golden、帮助文案（告知"超时会替你做什么"）同步。
