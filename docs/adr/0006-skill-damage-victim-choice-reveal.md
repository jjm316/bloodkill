# 技能伤害的亮牌权回归受害者自选

规则语料 `damage.reveal` 写明"每点伤害展示一个此前未展示的标记：玩家自选"，且九级技能表中只有感应者（rank 5）写"强制其展示 rank"。旧引擎却对一切 `source="skill"` 的伤害（刺客 2 点、感应者 1 点、炼金 harm 1 点）完全剥夺选择：rank 未亮则第 1 点直接亮 rank，否则自动亮一张标记（engine.py:734-736）。产品方裁定（2026-10-03 规则共识访谈）：技能伤害回归 `damage.reveal` 通用规则——每一点开**受害者自选**的亮牌窗；感应者按技能文本维持强制亮 rank。

## Considered Options

- **维持引擎全自动（首伤亮 rank、后续自动亮标记）**：被否决——语料明文与之矛盾且无 ADR 记录，且"自动亮哪张"由 Python 集合迭代序决定，实测随 PYTHONHASHSEED 翻转（同 seed 同命令得到不同日志），违反 ADR 0001 的回放确定性根基，golden 随机挂。
- **技能伤害剥夺选择但改成确定序**：修掉不确定性但保留剥夺；被否决——受害者"每点有得选"本就是伤害链基调，无理由为技能伤害开例外。

## Consequences

- 连带消灭两个缺陷：自动亮牌的跨进程不确定性（耦合点 A2）、审判者 wild 标记被强制定为玫色（A7）——自选窗路径本就正确处理 wild 色选。
- 引擎删除 skill 源的自动亮牌分支，并入通用亮牌管线；ruleset 版本随本批共识整体 bump（0.4 → 0.5），golden 与 `docs/rule-branch-coverage.md` 同步（第 102 行旧口径作废）。
- 联动 ADR 0009：受害者自选亮 rank 时将触发技能窗（旧规则下技能伤害亮 rank 不开窗）。
