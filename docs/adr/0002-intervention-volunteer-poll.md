# 干涉从"目标点名"改为全员公开自愿投票

来源 C 规则写「仅攻击目标可请求干涉」，旧实现更进一步把全部决定权给了被攻击者：目标可从所有有资格玩家中任点一人强制承伤，被点名者无拒绝权，其余玩家全程无操作。产品方裁定改为面桌语义：攻击声明后自动向全部有资格玩家开启公开自愿投票，全员表态（或超时视为不干涉）后攻击才实际结算——无人自愿则攻击正常结算，恰一人自愿则干涉必然发生（目标无权拒绝），多人自愿时目标可选其一或全部拒绝。

## Considered Options

- **保密唱票（全部答完才揭示结果）**：后答者无信息优势，博弈更干净；被否决——实时公开更接近面桌口头喊话的体验，产品方明确选择后者，并接受后答者的顺序信息优势。
- **保留目标点名模型**：改动最小；被否决——承伤同意权应归干涉者本人，这是本次重构的核心诉求。

## Consequences

- 命令与事件协议变更（`request-intervention` 移除、新增逐人表态命令、`decline-intervention` 收窄为多人自愿分支的目标专属），进行中的旧存档不做兼容（见规则语料 2026-09-04 裁决）。
- 干涉超时（房主开局配置，默认 90 秒）与带确认/取消的通用弹窗均按可复用抽象实现，本期只接入干涉投票与目标三选一两处，后续窗口按需接入。
- "默认不挡刀"为纯客户端偏好（localStorage 代发"不干涉"），不进入对局事件历史；断线玩家的兜底由服务端超时承担。
