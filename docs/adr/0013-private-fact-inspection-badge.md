# 小丑检视结果的私有事实角标（三分信息模型）

等级3（小丑）技能让玩家秘密查看两名玩家的阵营与等级（语料 B11：仅自己可见）。实现时发现客户端只有两类信息的展示语言：公开亮牌事实（线索槽，进投影全员可见）与私有猜测（备忘标记，ADR 0004：纯客户端 localStorage）。检视结果两头都不是——它是**服务端对局状态的私有投影**：进投影、仅本人可见、断线重连不丢，但绝非全员公开。

2026-10-11 拍板（原型四变体翻牌，验收产物 `.scratch/prototype-inspect-badge/`）：检视结果以**座位卡事实角标**展示（眼睛角点变体 A），与备忘角标同位区常驻并存——事实角标恒在备忘角标左侧（`right:22` vs `right:-8`），有无备忘不跳动。由此信息模型三分：

1. **公开事实**：线索槽/已亮标记——进投影，全员可见；
2. **私有猜测**：备忘标记（ADR 0004）——不进投影，本机 localStorage，可编辑；
3. **私有事实**：检视标记——进 `viewer.inspections`（仅接收者 viewer 块），只读。

同批修复：`SkillUse` 此前没有两人组合（`targetPlayerIds`）分支，等级3技能窗只渲染裸「使用技能」按钮，点击发出无目标命令被引擎以 `skill.invalid-target` 拒绝（用户所见"点释放技能弹报错且无效果"）。选择器改为两步下拉（每组合一按钮在 7–11 人局达 15–45 个，不可用），未选满两名不同玩家前禁用。

## Considered Options

- **检视结果写入备忘标记（复用现有角标）**：被否决——备忘=猜测是 ADR 0004 的核心不变量，混入服务端事实后"与公开亮牌矛盾时无需一致"的推理链断裂，且检视结果会随"清除备忘"消失。
- **动作区/事件流上方的私有序文**：被否决——一次性提示，错过即忘；检视是对局全程有效的情报，须常驻目标座位上（回头看时语境最强）。
- **区分记号走纯形状（白环/盾形）或文字 chip**：原型 B/C/D 被否决——A 的眼睛角点「看过」语义最直白，白底角点对三色背景对比度全达标（4.69:1–20.21:1）。
- **每组合一个按钮**：被否决——组合数 O(n²)，11 人局 45 个按钮。

## Consequences

- 引擎/服务端/协议零改动（`viewer.inspections` 投影字段早已存在，`HarlequinInspected` 事件已过滤目标内容，B11 共识原样）；golden、ruleset、协议版本均不动。
- 事实角标是只读 `span`（非按钮、无选择器），UI 上不存在任何把事实写回备忘的通路；两者视觉并存且可区分（CONTEXT.md「检视标记」词条）。
- 回放页与旁观者投影无 `viewer` 块，事实角标自然不渲染，无需特判。
- 帮助图例新增「检视标记」一条；小丑技能文案指向该图例。
- 后续若出现同类私有事实（如未来技能的私下情报），沿三分模型走投影+只读角标，不再新增 localStorage 事实位。
