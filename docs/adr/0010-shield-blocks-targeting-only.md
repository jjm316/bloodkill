# 盾只挡"被指定为目标"：持盾狂战士可以反伤

规则语料中盾的语义只有一条：受盾保护者不能成为攻击或强制伤害目标。旧引擎却额外规定**持有盾的狂战士自己不能发动反伤**（engine.py:580-581 直接 raise `target.shielded`，投影同步只给"放弃"选项），无任何规则出处。该检查的唯一触发链是：守护者给狂战士盾 → 狂战士志愿挡刀承伤 → 被迫亮 rank 开出技能窗 → 却因自己的盾不能反伤——效果上盾"没收"了狂战士的技能，且挡刀开窗后"被迫放弃"会按 ADR 0008 永久烧掉技能资格，玩家从任何文案都推不出来。产品方裁定（2026-10-03 规则共识访谈）：**删除 owner 盾检查**，盾只挡"被指定为目标"。

## Considered Options

- **维持禁止并确立总则"持盾者不能发动伤害型技能"**：被否决——这条总则今天并不存在（持盾刺客/感应者/炼金 harm 都能正常发动），真要总则化会波及所有持盾者并扩大"被迫放弃陷阱"；只做狂战特例则是无出处的隐藏 debuff。
- **放开（删 owner 检查）**：盾回到纯防御定位（防具），反伤目标是攻击者——若**攻击者**持盾则反伤被拦截（有规则出处，保留）。产品方选择此案。

## Consequences

- 引擎删 owner 盾检查、投影恢复反伤选项；ruleset 随本批共识 bump（0.4 → 0.5），相关分支测试改写。
- 不变的边界：持盾者仍不可被攻击/技能指定（耦合点 B1）、持盾者仍可挡刀并正常承伤（B2，2026-08-22 裁决）、守护者第 3 点伤害剑盾成对归还（B7）。
- 战略面：守护者给狂战士盾从此是纯增益，不再附带"禁反伤"的隐性代价。
