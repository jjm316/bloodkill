# 账号管理工具使用指南

面向产品方运维的管理命令用法：在服务器终端查看账号与房间、重置玩家密码、
确认并备份关闭一个弃局房间。命令随服务端一起交付（`server/admin.py`），
不需要额外安装；**只有能登录服务器终端的运维人员使用**，没有公网管理页面，
普通玩家账号、房主身份和外网请求都拿不到管理权限。

## 命令一览

| 命令 | 作用 |
| --- | --- |
| `users` | 查看账号及其当前房间占用（用户名、稳定账号引用、房间号） |
| `rooms` | 查看房间号、对局引用、状态、房主、玩家与在线情况 |
| `reset-password 用户名` | 交互隐藏输入新密码，重置并撤销该账号全部登录 |
| `close-room 房间号` | 预览、再次输入房号确认后备份并关闭一个弃局房间 |

管理命令**不直接读写存档文件**，而是请求正在运行的服务执行操作：服务启动时
在同一进程打开一个只绑定本机回环地址（127.0.0.1）的管理监听，CLI 凭存档目录
里的独立管理凭证（`admin/admin-token`，不出现在命令行参数或任何输出中）访问
它。因此**使用前提是服务正在运行**；服务停止时只能先启动服务再操作。

## 运行环境与进入目录

### 本地（Windows 仓库）

先按仓库 `README.md` 启动服务（开发模式或单服务器模式均可），另开一个终端，
在**仓库根目录**运行：

```powershell
.\.venv\Scripts\python.exe -m server.admin users
.\.venv\Scripts\python.exe -m server.admin rooms
.\.venv\Scripts\python.exe -m server.admin reset-password 小明
.\.venv\Scripts\python.exe -m server.admin close-room 123456
```

默认存档目录是仓库根的 `saves/`（与服务一致）；用环境变量
`BLOOD_BOUND_SAVES_DIR` 启动了自定义存档目录时，CLI 也读同一环境变量。

### 云服务器（阿里云轻量，`/opt/bloodkill`）

1. 阿里云控制台或本地终端执行 `ssh root@<服务器IP>` 登录服务器。
2. `cd /opt/bloodkill` 进入部署根目录（服务由 systemd 托管，可用
   `systemctl status bloodkill` 确认正在运行；更新与日常运维见
   [云服务器部署](deployment-cloud.md)）。
3. 运行：

```bash
.venv/bin/python -m server.admin users
.venv/bin/python -m server.admin rooms
.venv/bin/python -m server.admin reset-password 小明
.venv/bin/python -m server.admin close-room 123456
```

云端存档目录默认是 `/opt/bloodkill/saves`（systemd unit 的
`WorkingDirectory=/opt/bloodkill`，存档按 `./saves` 相对解析），在部署根目录
运行命令即可对上，无需额外参数。

以下所有命令的输出与管理行为在本地与云端布局下一致。

## 查看目标：users 与 rooms

处理任何账号或房间之前，先查看确认目标：

```text
$ python -m server.admin users
共 3 个账号：
用户名    账号引用                          房间号
演示房主  c3b88a30c5d60756ed2fedd5986560ee  124302
演示玩家  98d6e3ac65f4daaed132218eeba6d65f  124302
演示路人  9d5023f97d24f8ec314ade100be60551  （未占用）

$ python -m server.admin rooms
共 1 个房间（等待中 1 个）：
房间 124302｜对局 g-09585cf0fa0c｜等待中｜未锁定｜房主 演示房主
  玩家 2 人：演示房主（离线）、演示玩家（离线）
```

- `users` 每行一个账号：用户名、稳定账号引用（排查问题时给开发者的标识）、
  当前未结束房间的占用房号；没有占用显示「（未占用）」。已结束的房间不算占用。
- `rooms` 每个房间两行：房号、对局引用、状态（等待中/进行中/已结束）、锁定
  情况、房主；下一行是全部玩家及在线/离线（以当时的真实连接为准）。
- 输出不含密码摘要、会话凭证或房主令牌，可以直接截图留档。

可选参数（本地与云端通用，两个子命令与全局位置都可以放）：

- `--saves-dir DIR`：显式指定存档目录（默认取环境变量 `BLOOD_BOUND_SAVES_DIR`
  或当前目录的 `./saves`）。**必须与服务启动时的存档目录一致**。
- `--port N`：显式指定管理端口（默认读存档目录 `admin/installation.json` 里
  记录的端口，一般不需要传）。

## 重置密码：reset-password 用户名

忘记密码没有自助找回（不收邮箱/手机号）；由产品方线下核实本人后用此命令重置。

```text
$ python -m server.admin reset-password 演示玩家
请输入新密码（6–12 个字符，直接回车取消）：
请再次输入新密码确认（直接回车取消）：
已重置账号「演示玩家」的密码；该账号全部登录已撤销（所有设备）。
共撤销登录会话 2 个，停止已建立的房间连接 1 条。
座位与房主归属保持不变；该账号需用新密码重新登录。
```

（会话数与连接数以该账号当时的真实登录为准；上面是新密码输入不回显的真实
输出形态，终端里两行提示后直接出现成功说明。）

- 密码经**隐藏输入**读取：终端里不回显（输入时屏幕不显示任何字符是正常现象），
  也不会出现在命令行参数、输出或日志中。输入两次且完全一致才提交；新密码须
  6–12 个字符。
- 校验失败的中文提示后可直接重试；**直接回车（空输入）即取消**，非零退出，
  不修改任何账号。
- 成功后该账号在**所有设备**的登录全部撤销、已建立的房间连接被停止并收到
  中文说明；座位与房主归属保持不变，玩家用新密码重新登录即可恢复原房间。

常见反馈：

- 账号不存在：`失败：账号「未知账号」不存在，未修改任何账号；管理工具不会自动创建账号。`
  （用户名区分大小写写法，但英文大小写不构成不同账号，先在 `users` 里核对。）
- 长度不符：`密码须为 6–12 个字符，请重新输入。`
- 两次不一致：`两次输入的密码不一致，请重新输入。`
- 取消：`已取消：未修改任何账号。`

## 关闭弃局房间：close-room 房间号

玩家中途散场又没有终局的房间（等待中/进行中的弃局）用此命令清理：先备份、
再关闭，释放该房全部玩家的占用，让大家能开下一局。**一次只处理一个房间，
不能用清空存档目录代替单房清理。**

流程：先用 `rooms` 找到要处理的房号，然后运行 `close-room 房间号`。命令会
先显示该房当前信息（预览），要求**再次输入同一房号**确认：

```text
$ python -m server.admin close-room 124302
将要关闭的房间：
房间 124302｜对局 g-09585cf0fa0c｜等待中｜未锁定｜房主 演示房主
  玩家 2 人：演示房主（离线）、演示玩家（离线）
关闭将先备份该房存档，再停止其操作与计时器、断开全部连接并释放玩家占用；这不是正常终局，不产生胜负或身份揭晓。
再次输入房号 124302 确认关闭（其他输入或直接回车取消）：124302
已关闭房间 124302。
受影响玩家 2 人：演示房主、演示玩家
备份已写入：C:\...\saves\admin-backup\g-09585cf0fa0c
```

- 预览后如果目标发生了变化（有人开局或行动），确认会被拒绝并提示重新预览，
  不会误关变化后的房间。
- 确认时输入其他内容或直接回车即取消：`已取消：输入与房间号不一致，未关闭房间 124302。`
- 关闭语义：**不是正常终局**——不产生胜负或身份揭晓；被关闭的房间不能重新
  加入或在线回放；服务重启不会恢复它，也不重新占用账号。其他房间不受影响，
  无需停服。
- 玩家侧会立即收到「房间已被管理员关闭，请返回大厅创建或加入新的房间。」
  的中文通知，占用释放后即可开下一局。

备份位置：存档目录下隔离的 `admin-backup/<对局号>/`，固定三件
`game.json.gz`（对局存档）、`meta.json`（房间元数据与座位归属）、
`closure.json`（关闭事实：房号、对局号、受影响玩家、备份路径）。成功输出会
打印备份绝对路径；房间恢复扫描与「最近 20 个正常终局」的回放清理都不会触碰
这个目录，游戏数据清理也不会删除账号。

常见反馈（均为非零退出，房间不被误动）：

- 房间不存在：`失败：房间 654321 不存在，请核对房间号。`
- 已正常结束：`失败：房间 124302 已正常结束，无需管理关闭；回放照常保留。`
- 已被管理关闭（重复处理）：`失败：房间 124302 已于 2026-10-13 22:35:13 被管理关闭，无需重复处理。`
- 备份失败：`失败：备份失败（…）。房间 124302 未关闭，保持可用；请处理备份目录后重试。`
  （备份失败则不关闭；处理完备份目录后重试会整目录重写同一备份。）

## 配置不匹配与服务未运行时的处理

管理命令启动时先做防误连核对：读取存档目录 `admin/` 里的安装标识与端口记录，
并确认端口上正是这个存档目录对应的服务实例；不符即拒绝操作。这保证同一台
机器上跑多个服务实例时不会误操作另一个。

- 服务未运行：

  ```text
  失败：无法连接 127.0.0.1:8001 上的管理端口（[WinError 10061] 由于目标计算机积极拒绝，无法连接。）。服务可能未运行或端口已变化。请确认服务正在运行、--saves-dir 与服务启动时的存档目录一致。
  ```

  处理：先启动（云端 `systemctl restart bloodkill`，本地按 README 启动
  uvicorn），再重试命令。
- 存档目录不对（该目录从未启动过服务）：

  ```text
  失败：存档目录 C:\…\示例目录 中没有可用的管理配置（admin/installation.json）。服务可能从未在此存档目录启动过；请核对 --saves-dir。
  ```

  处理：核对服务实际使用的存档目录（云端即 `/opt/bloodkill/saves`，本地看
  启动时是否设置了 `BLOOD_BOUND_SAVES_DIR`），用 `--saves-dir` 指过去或在
  正确目录里运行。
- 端口上不是目标实例（误连防护）：

  ```text
  失败：端口 8002 上是另一个服务实例（安装标识或存档目录与 C:\…\saves 不匹配），已拒绝查询。请核对 --port 与 --saves-dir，避免误操作其他服务。
  ```

  处理：`--port` 只在同时运行多个实例时才需要；去掉它让 CLI 读记录端口，或
  核对每个实例各自的存档目录。
- 管理凭证问题（凭证文件被改动/缺失）：按提示核对 `admin/admin-token`；凭证
  由服务首次启动时生成，同目录重启复用，手工改动需重启服务生效。

## 更新与数据保留

云端部署与更新是同一条命令（见 [云服务器部署](deployment-cloud.md)）：
`scripts/deploy-cloud.sh <服务器IP>` 在本机构建前端、打包 `server/`、
`blood_bound/`、`client/dist/` 与 systemd unit 上传解包并重启服务。
**打包清单不包含 `saves/`**，正常更新不会触碰它，以下内容全部保留：

- 账号与登录会话（`accounts/accounts.sqlite3`）：未过期的登录在更新后仍然
  有效，已退出/被撤销的登录不会被复活；
- 房间占用与房主归属：等待中/进行中的房间照常恢复，玩家座位不变；
- 管理凭证与安装记录（`admin/`）：更新后无需重新配置即可继续使用管理命令；
- 管理备份（`admin-backup/`）与旧房间切换备份（`legacy-backup/`）：
  已关闭的房间更新后依旧保持关闭，不会复活或重新占用账号。

管理清理只改变明确指定的目标房间；`users`/`rooms` 查看是只读操作，不产生
任何写入。若更新后需要清理弃局，照常 `rooms` 查看、`close-room 房间号` 处理。
