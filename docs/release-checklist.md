# 鲜血盟约发布检查表

## 构建与验证

- [ ] 使用 Python 3.11+，运行 `python -m unittest discover -v`。
- [ ] 在 `client/` 运行 `npm ci` 和 `npm run build`，确认生成 `client/dist/`。
- [ ] 启动服务后运行 `python scripts/release_smoke.py --base-url http://127.0.0.1:8000`（需安装服务端 requirements）。
- [ ] 浏览器完成创建房间、加入、开始对局、操作、断线重连和回放 smoke 流程。
- [ ] 用键盘完成首屏、房间操作和回放控制；焦点始终可见，错误可被读屏播报。

## 性能预算

- 首屏静态资源（压缩后）不超过 350 KiB。
- 桌面端首屏加载不超过 2 秒，移动端在本地局域网不超过 4 秒。
- 对局事件日志最多保留最近 120 条，单次状态更新不应触发无关座位重绘。
- 服务端 `/health` 响应时间目标低于 200 ms；`/metrics` 不返回身份、种子或房间内容。

## 发布与回滚

- [ ] 备份 `BLOOD_BOUND_SAVES_DIR` 目录及其权限。
- [ ] 反向代理启用 HTTPS/WSS；公网访问不得暴露明文 HTTP/WS。
- [ ] 仅开放应用端口，管理端点按需限制在内网。
- [ ] 发布后检查 `/health`、`/metrics`，确认活动连接和房间计数正常。
- [ ] 回滚时停止新进程、恢复上一版本代码与 saves 备份，再运行 smoke 脚本。

## 隐私与诊断

- [ ] 日志只记录事件 ID、命令 ID、修订号和错误代码，不记录身份、诅咒或 host token。
- [ ] 将崩溃时间、版本、浏览器和可复现的 seed/命令序列提供给维护者。
- [ ] 不把 `/metrics`、保存目录或 host token 放入公网穿透配置。
