# 事件日志分类与筛选（选项卡屏蔽 + 行首类别标签）

Type: task
Status: resolved（2026-09-07 实现，commit 668471c；GUI 验收记录见本文件末尾 Comments）
CONTEXT.md 已增"事件日志""事件类别"词条；遵循 ADR 0004 的 client-only 原则（本决策是其直接应用，不新增 ADR）
裁决日期: 2026-09-05（产品方 grilling 裁决）

## Problem Statement

（从玩家视角描述）事件日志是一份无差别的平铺流水：一次攻击会刷出表决开启 + 全员逐条表态 + 三选一 + 选定共 5 条以上记录，技能与治疗的后果又各占一行，真正想盯的"谁打了谁、谁亮了牌"很快被淹没。玩家无法按关注方向阅读，也无法暂时屏蔽不关心的类别。另外有 9 种事件至今显示为"游戏事件"加空描述，日志里存在无意义行。

## Solution

事件日志顶部加一排筛选选项卡：一个"全选"加六个**事件类别**（匕首 / 干涉 / 技能 / 亮牌 / 资源 / 流程）。选中=显示该类别，取消勾选=屏蔽该类别，列表只显示选中类别的条目（对整份历史生效）。每条日志行首显示带类别专属颜色的类别标签，与选项卡同色同词，扫一眼颜色即知归属；类别标签替代现有的事件短名前缀。屏蔽偏好保存在本机 localStorage，刷新、断线重连、换房、开新局都不丢。顺手补全 6 种缺失的中文描述；3 种"窗口开启"类待办事件从日志隐藏（引擎照发，仅前端不渲染）。纯前端功能，服务端与协议零改动。

## User Stories

1. As a 玩家, I want 事件日志顶部有一排筛选选项卡（全选 + 六个事件类别）, so that 我能按关注方向筛选阅读。
2. As a 玩家, I want 取消某类别的选中后日志不再显示该类条目, so that 全员表态刷屏这类噪音消失。
3. As a 玩家, I want 重新勾选后该类别的历史条目立即恢复显示, so that 筛选对整份历史生效而非只对新事件生效。
4. As a 玩家, I want 尚未全选时点击"全选"即选中全部类别, so that 一键恢复完整日志。
5. As a 玩家, I want 已全选时点击"全选"即全部取消, so that 我能一键清空后只勾想看的类别。
6. As a 玩家, I want "全选"的选中态与各选项卡联动（全部选中时亮、否则灭）, so that 一眼看出当前是不是完整视图。
7. As a 玩家, I want 每个选项卡有清晰可辨的选中/未选中两种视觉状态, so that 我不会猜错当前的筛选范围。
8. As a 玩家, I want 全部类别都被取消时日志区显示一行灰字"已屏蔽全部类别", so that 空列表不会被误认为没有事件。
9. As a 玩家, I want 每条日志行首显示类别标签（如"匕首"）, so that 不动筛选也知道这条是什么性质。
10. As a 玩家, I want 类别标签带类别专属颜色且与对应选项卡同色, so that 扫颜色即可对上选项卡。
11. As a 玩家, I want 类别标签替代原来的事件短名前缀, so that 行首不堆叠两套前缀、每行更短。
12. As a 玩家, I want 每条日志的描述文案自足（去掉短名也能读懂）, so that 替换前缀后信息不损失。
13. As a 玩家, I want 消耗资源、归还资源、治疗、丑角检视、归还标记等此前显示"游戏事件"的条目有完整中文描述, so that 日志不再有无意义行。
14. As a 玩家, I want 亮牌窗口、技能窗口、归还标记窗口这三类"待办窗口开启"事件不出现在日志中, so that 日志只留叙事，不与待办 UI 重复。
15. As a 玩家, I want 屏蔽偏好保存在本机 localStorage, so that 刷新、断线重连后不用重新勾选。
16. As a 玩家, I want 屏蔽偏好跨房间、跨对局保留（不随新对局清空）, so that 阅读偏好不需要每局重设。
17. As a 玩家, I want 首次使用（本机无存储偏好）时默认显示全部类别, so that 新玩家看到完整日志。
18. As a 玩家, I want 屏蔽只影响我自己设备上的显示, so that 其他玩家的视图不受影响。
19. As a 玩家, I want 折叠标题"事件日志（N）"的 N 为当前过滤后可见条数, so that 计数与我看到的列表一致。
20. As a 玩家, I want 勾选状态变化时列表即时更新, so that 反馈无延迟、可快速试组合。
21. As a 手机玩家, I want 选项卡在窄屏下可换行、点按区域足够大不误触, so that 手机上好用。
22. As a 观众, I want 同样能使用选项卡筛选日志, so that 观战阅读体验与玩家一致。
23. As a 玩家, I want 类别映射覆盖当前全部公开事件类型, so that 任何事件都有归属、不会因未映射而被漏掉。
24. As a 玩家, I want 未映射的新事件类型归入"流程"兜底且照常显示, so that 后端新增事件不会在筛选下凭空消失。
25. As a 玩家, I want 本功能不改协议、不发新事件、不加服务端字段, so that 规则版本、存档与重放完全不受影响。
26. As a 开发者, I want 事件类别映射是一张集中的纯数据表（与界面组件分离）, so that 后端新增事件类型时只需补一行，未来测试基建就位后可直接单测。

## Implementation Decisions

- **六类事件类别及归属**（每条事件恰属一类；括号内为协议 eventType）：
  - **匕首**：匕首传递（DaggerPassed）、宣布攻击（AttackDeclared）、受到伤害（DamageApplied）、被捕获（PlayerCaptured）。
  - **干涉**：表决开启（InterventionPollOpened）、玩家表态（InterventionResponded）、三选一开启（InterventionChoiceOpened）、选定挡刀者（InterventionSelected）、干涉未发生（InterventionDeclined）。
  - **技能**：技能窗口开启（SkillWindowOpened，仅指映射归属，见隐藏决策）、使用技能（SkillUsed）、放弃技能（SkillDeclined）、丑角检视（HarlequinInspected）、治疗伤害（DamageHealed）、归还身份标记（TokenReturned）、身份标记被遮蔽（IdentityMarkersObscured）、归还窗口开启（TokenReturnOpened，同上）。
  - **亮牌**：亮出线索（ClueRevealed）、亮牌窗口开启（RevealWindowOpened，同上）。
  - **资源**：获得资源（ResourceGranted）、消耗资源（ResourceSpent）、归还资源（ResourceReturned）。
  - **流程**：加入房间（PlayerJoined）、开局（GameStarted）、结束（GameEnded）、阶段切换（PhaseChanged）、开局徽记展示（ClueIconsShown）。
  - 私有事件（诅咒分发/查看）服务端本就不广播，与映射无关。
- **client-only**：前端集中维护一张 `eventType → 事件类别` 纯数据映射表，独立于界面组件存放；不改协议、不改引擎、不加服务端字段。未映射类型兜底归"流程"且照常显示（保证不消失）。
- **筛选与屏蔽是一个机制**：选项卡选中=显示、取消=屏蔽，没有独立的屏蔽设置区。
- **全选语义**：未全选时点击=全选；已全选时点击=全部取消；全选的选中态随各选项卡联动派生。
- **全不选**：列表区显示灰字"已屏蔽全部类别"。
- **行首标签**：带类别色的类别标签替代现有事件短名前缀；标签词与选项卡词一致（匕首/干涉/技能/亮牌/资源/流程）。六色须与现有界面主题协调且互相可辨。
- **隐藏窗口事件**：RevealWindowOpened、SkillWindowOpened、TokenReturnOpened 在前端渲染层不显示（引擎照发、缓冲照存）；其余全部事件显示。
- **描述补全**：ResourceSpent、ResourceReturned、DamageHealed、HarlequinInspected、TokenReturned 共 5 种公开事件补中文短名与描述，且全部现有描述须达到"自足"标准（玩家 ID 继续换算为显示名）。
- **偏好持久化**：屏蔽勾选存 localStorage（沿用 `bloodbound:*` 键前缀惯例），键为设备级全局，不按房间/对局区分、不随新对局清空——与备忘标记（按对局存、跨局清空）刻意不同，因为这是阅读偏好不是对局推理。
- **计数**："事件日志（N）"的 N = 过滤后可见条数。
- **默认态**：无存储偏好时全部类别选中。
- **缓冲不变**：现有事件缓冲容量与"最近 60 条倒序"的渲染上限维持现状。

## Testing Decisions

- 前端目前没有自动化测试设施（`frontend-test-infra` 是独立待办 issue），本功能不引入新测试框架，走现有最高接缝：**真实浏览器 GUI 黑盒验证**（用 test toolkit 起服，浏览器自动化操作页面）。好的测试只验玩家可见行为，不测内部实现。
- 必验场景清单：
  1. 六类事件各至少一条出现，行首标签词与颜色正确，且与选项卡颜色一一对应。
  2. 取消勾选后历史条目即时消失、后续同类新事件也不显示；重新勾选全部恢复。
  3. "全选"两个方向都有效；联动选中态正确。
  4. 全不选时出现"已屏蔽全部类别"灰字。
  5. 刷新页面后屏蔽偏好保留；开新对局不清空。
  6. 三种窗口事件不出现在日志；5 种补描述事件文案完整、玩家 ID 已换成显示名。
  7. "事件日志（N）"的 N 与可见条数一致。
  8. 窄屏（手机宽度）下选项卡换行可用、不误触。
  9. 真实加载验证：build 通过不等于能渲染（React Hook 顺序教训），必须真实打开页面确认无白屏。
- 映射表完整性靠代码评审对照引擎全部 `_event` 调用清单核对，不做自动化。

## Out of Scope

- 前端自动化测试基建（独立 issue `frontend-test-infra`）。
- 按玩家过滤、关键字搜索、时间戳显示。
- 未读计数、新事件高亮、声音提醒等通知机制。
- 服务端事件结构与广播逻辑的任何改动。
- 回放页（不渲染事件日志，本功能不涉及）。
- 事件日志折叠/展开交互本身的改造。

## Further Notes

- 后端新增事件类型时的惯例：必须同步在前端映射表补一行（漏了会兜底进"流程"，不消失但分类不准）。建议写进 CONTEXT.md 或开发惯例文档的一句话提醒。
- 六个类别色的具体色值留给实现，约束：互相可辨、与选项卡同色、适配现有主题。
