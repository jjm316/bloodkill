# 事件日志模块深化

Type: task
Status: resolved

用户于 2026-10-06 选择架构报告第二项，并确认完整范围实施。

## 问题

分类和可见性在 eventLog.ts，中文描述与渲染在 GameScreen.tsx；新增事件需要同步多处。
原类别完整性测试只检查类别是否合法，漏映射后回退流程仍能通过。

## 已确认范围

- 房间页面只向事件日志传入 events、players；分类、文案、可见性、筛选和本机偏好由日志模块拥有。
- 每种事件的类别、中文描述与可见性集中定义，呈现代码与阅读模型分文件存放。
- 已知事件文案保持一致；补全开局阶段 setup 的“开局准备”中文名，修复浏览器验收发现的内部 ID 展示。
- 未知事件归流程、继续可见，使用“发生了一条新的对局事件”中文兜底，不展示原始事件 ID 或 payload。
- 保留六类筛选、全选双向语义、全部屏蔽提示、过滤后计数、三种窗口事件隐藏。
- 保留过滤后最近 60 条倒序展示，原事件缓冲不变。
- 筛选偏好继续使用 bloodbound:event-log-filter，设备级跨房间/跨对局保留；存储不可用时本次挂载仍可筛选。
- 遵守 ADR 0001、0005：事件权威事实不变，实时文案使用等级数字。

## 验证

- 日志渲染入口验证六类、筛选更新、全选、重新挂载、换局、展示上限、空事件更新及存储不可用。
- 阅读模型验证已知事件准确类别和中文描述；清单与引擎公开事件核对，已知流程事件漏定义也必须失败。
- 保留门控与超时日志原有回归测试；通过 TypeScript 检查、前端全套测试与构建。
- 按 implement 技能完成标准/需求两轴复核，提交到当前分支。

## 范围外

服务端、协议、规则、回放页面、事件缓冲容量、样式与交互布局均无需修改。
