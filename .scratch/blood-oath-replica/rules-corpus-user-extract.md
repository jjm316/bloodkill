## 可作为当前规范的规则

| 规则 ID | 规则摘要 | 待验收重点 |
| --- | --- | --- |
| `setup.equal-factions` | 6–12 人；偶数人数时从 Rose、Beast 各选取玩家数一半的不重复身份 | 两阵营人数相等；两张审判者不入局 |
| `setup.inquisitor` | 奇数人数时从两张审判者中随机选一张，Rose/Beast 各选取人数向下取整的一半；每名审判者对应 1 张真诅咒和 1 张假诅咒 | 诅咒卡数量按审判者人数计算 |
| `setup.clue-icon` | 每位玩家只向其左手边玩家展示 clue icon | Harlequin 的 clue icon 为敌对家族；审判者虽显示 Rose/Beast clue 但真实属于 Secret Order |
| `turn.dagger-holder` | 只有匕首持有者主动行动；可传递匕首或攻击任意玩家 | 攻击后匕首交给攻击目标 |
| `damage.reveal` | 每点伤害展示一个此前未展示的标记：玩家自选等级（rank）或身份标记（红/蓝/？），身份标记组合由 rank 决定。本条适用于**一切伤害源**（攻击/挡刀/技能/反伤），受害者均有选择权 | 第 3 点被迫展示 rank、第 4 点被捕获；仅审判者 wild 可自选玫/兽/问号（窗口超时默认问号） |
| `intervention.poll` | 攻击声明后自动向全部有资格玩家（存活、非攻击方、非目标、rank 未展示、目标未持扇）开启公开自愿投票；全员表态或超时视为不干涉后方可结算；恰一人自愿则干涉必然发生，多人自愿时目标可选其一或全部拒绝，无人自愿则攻击正常结算 | 干涉者承伤并强制展示 rank；技能伤害不可干涉；干涉超时由房主开局配置（默认 90 秒） |
| `window.single-timeout` | 亮牌窗/技能窗/退牌窗三类单人窗口设超时兜底：到期自动执行确定性默认——亮牌窗亮排序第一张（marker-0 → marker-1 → rank）、wild 色选窗取问号、技能窗视为放弃（即弃用，永久失去）、退牌窗退排序第一张（marker 先于 rank） | 房主开局单项配置"单人窗口超时"，三类窗口共用，预设 30/60/90/120/180 秒、默认 90 秒；超时由 DeadlineScheduler 代发 timeout 命令，引擎不存墙钟 |
| `skill.reveal-rank` | rank 被**任何伤害**（攻击/挡刀/技能/反伤，自选或被迫）**新亮出**时，立刻开启对应角色技能的技能窗；唯一例外：感应者（rank 5）强制亮出的 rank 不开窗，且永久封印该玩家技能 | 技能伤害永不触发干涉投票；技能已使用或已弃用者永不再开窗（炼金治疗亦无技能复活效果）；被感应者封印 = 诅咒胜路当场作废 |
| `game.end` | 任一玩家第 4 点伤害被捕获时立即结束 | 家族 active player 按领袖规则判定；审判者造成第 4 点伤害时走独立失败分支 |
| `inquisitor.attack-limit` | 审判者不能攻击已受 3 点伤害的玩家 | 禁止命令必须带可解释原因 |
| `inquisitor.curse` | 审判者在诅咒技能窗口中发动：将真诅咒与假诅咒暗置分发给不同玩家，或放弃（诅咒永留供应区） | True Curse 在正常胜方领袖前时，审判者独赢；审判者被捕获也独赢 |
| `inquisitor.capture-branch` | 审判者作为 active player 造成第 4 点伤害时，审判者自身判负，其他方按该分支获胜 | 不把审判者临时归入 Rose/Beast |

## 角色能力语义

下表是来源 C 的行为改写，供引擎使用；不是原始卡牌文案或 UI 显示文本。每个家族各有一张相同规则的 1–9 身份。

| Rank | 规则 ID | 能力语义 |
| --- | --- | --- |
| 1 | `elder` | 取得 Quill；本家族领袖改为等级最高的角色。 |
| 2 | `assassin` | 指定一名玩家承受 2 点伤害，再将匕首交给该玩家。 |
| 3 | `harlequin` | 秘密查看两名玩家的角色；其 clue icon 显示敌对家族。 |
| 4 | `alchemist` | 仅在自己干涉后，可令被干涉者承受或治疗 1 点伤害；治疗时该玩家退回任一已展示 token。技能效果仅限治疗与伤害，**不附带任何技能复活**。 |
| 5 | `mentalist` | 指定一名玩家承受 1 点伤害，强制其展示 rank（若已展示则改为展示一张身份标记）。再将匕首交给该玩家。被其强制亮出 rank 的玩家技能被**永久封印**，炼金治疗退回 rank 亦不可解。 |
| 6 | `guardian` | 向一名玩家给出同色 Shield，自己取得匹配 Sword。受 Shield 保护者不能成为攻击或强制伤害目标，但可干涉并正常承伤。持 Sword 的 Guardian 第 3 点伤害时，归还该 Sword 与对应 Shield。 |
| 7 | `berserker` | 令刚刚攻击自己的玩家承受 1 点伤害。 |
| 8 | `mage` | 给一名玩家 Staff；该玩家的身份标记全部变为问号（?）。 |
| 9 | `courtesan` | 向一名玩家给出 Fan；该玩家成为攻击目标时，他人不能干涉。 |
| fleur cross | `inquisitor` | 两张审判者仅 clue icon 不同，共用同一个 fleur cross rank token；诅咒分发为亮等级技能（见 `inquisitor.curse`），其窗口触发与 `skill.reveal-rank` 同一总则——非感应者伤害新亮出 fleur-cross 即开窗，被感应者封印则诅咒胜路当场作废；其 affiliation 为 wild，且不能攻击已受 3 点伤害者；wild 身份标记亮出时自选玫/兽/问号（窗口超时默认问号）。被捕获或满足 True Curse 夺胜条件时独赢。 |

### 身份标记组成（2026-08-22 澄清）

每名玩家 3 张标记：1 张等级（rank 1–9）+ 2 张身份标记（红/蓝/？）。身份标记组合由 rank 决定：

| Rank | 红方身份标记 | 蓝方身份标记 |
| --- | --- | --- |
| 1 长老 | 红 红 | 蓝 蓝 |
| 2 刺客 | ? ? | ? ? |
| 3 小丑 | ? ? | ? ? |
| 4 炼金术师 | ? ? | ? ? |
| 5 感应者 | 红 红 | 蓝 蓝 |
| 6 守护者 | 红 红 | 蓝 蓝 |
| 7 狂战士 | 红 ? | 蓝 ? |
| 8 法师 | 红 ? | 蓝 ? |
| 9 交际花 | 红 ? | 蓝 ? |

受伤后玩家自选展示身份或 rank（通常先亮身份、尤其 `?` 藏阵营）；前 2 点可各亮 1 张身份，第 3 点被迫亮 rank；挡刀（干涉）被迫亮 rank 并开技能窗（decline = 永久失去技能）。

### 产品方裁决（2026-08-22）

来源 C 文本与产品方裁定冲突处，以产品方裁定为准：

- **Elder 领袖**：来源 C 写「羽毛 = 家族中除你外最小等级者代领」，产品方裁定为「领袖改为数字最大者（rank 9）」。上表 rank 1 已按「数字最大」书写。
- **Guardian 盾**：来源 C 写「持盾者不能响应干涉」，产品方裁定保留「可干涉」（不能成为攻击/强制伤害目标，但可响应干涉并正常承伤）。上表 rank 6 已按此书写。
- **Mage 法杖**：来源 C 有两条法杖文案，产品方裁定为「一个效果——给一名玩家 Staff，该玩家身份标记全变问号」。上表 rank 8 已按此书写。
- **Courtesan 扇**：来源 C 写「被攻击时无法请求干涉」，产品方裁定为「他人不能为该玩家干涉」。上表 rank 9 已按此书写。

### 产品方裁决（2026-09-04）

- **干涉模型重构**：来源 C 写「仅攻击目标可请求干涉」，产品方裁定改为「攻击声明后自动开启全员公开自愿投票」。同意权归干涉者本人：恰一人自愿时干涉必然发生（被攻击者无权拒绝），多人自愿时被攻击者可选其一或全部拒绝，无人自愿则攻击正常结算。表态实时公开、答后不可反悔；房主开局配置干涉超时（默认 90 秒，可选 30/60/90/120/180），投票阶段到期未表态视为不干涉，目标三选一阶段到期自动全部拒绝。玩家可在客户端设置"默认不挡刀"，开启后不弹确认、自动视为不干涉。上表 `intervention.poll` 已按此书写（原 `intervention.request` 废弃）。详见 `docs/adr/0002-intervention-volunteer-poll.md`。

### 产品方裁决（2026-09-05）

- **诅咒分发时机**：来源 C 只写 "when the Inquisitor uses his ability"，未锚定时机；首个实现把它做成全时段常驻的供应区动作。产品方裁定诅咒分发就是审判者的技能，与 rank 1–9 角色技能同一套流程：因攻击或挡刀（干涉）伤害亮出等级（fleur-cross）时开启唯一一次技能窗口，窗口内选择发动（真/假诅咒暗置分给不同玩家，客户端下拉框标注「真诅咒交给：/假诅咒交给：」并弹确认）或放弃；放弃或从未亮出等级则诅咒永留供应区、诅咒胜路作废。技能伤害不触发该窗口；已发动或放弃后不再出现第二次窗口。此裁决推翻"fleur-cross 是设置阶段能力、永不触发技能窗口"的旧设定。上表 `inquisitor.curse` 与 fleur cross 行已按此书写。详见 `docs/adr/0003-inquisitor-curse-as-reveal-triggered-skill.md`。

### 产品方裁决（2026-10-03）

本批裁决来自规则耦合全量扫描（30 个耦合点，`.scratch/rule-coupling-review/index.html`）的共识访谈。仲裁元规则：语料与引擎矛盾且无 ADR 记录时，默认采语料改引擎；但产品方本批亲口裁决效力最高，可直接推翻语料。主要裁决：

- **技能伤害亮牌权（P1，改引擎）**：技能造成的伤害，每一点回归 `damage.reveal` 通用规则——开**受害者自选**亮牌窗；感应者（rank 5）按技能文本维持**强制亮 rank**。连带消灭两个引擎缺陷：技能伤害自动亮牌的集合迭代序不确定性（A2）、wild 标记被强制玫色（A7）。
- **技能窗开窗总则与封印（P4，自定义规则，部分推翻旧表述"技能伤害不开窗"）**：rank 被**任何伤害**新亮出即开技能窗——无论来源（攻击/挡刀/技能/反伤）与谁选（被迫/自选）——**唯一例外是感应者的强制亮出**。被感应者点出等级 = 该玩家技能**绝对永久封印**（炼金治疗退回 rank 亦不可解，"炼金解封"不存在）。封印实现采方案 A：感应者亮出受害者 rank 时直接写入 `skills_used`，与已用/已弃用共用同一把永不清除的锁，不加新状态位/事件。技能伤害仍**永不触发干涉投票**。连带：狂战反伤亮 rank 也开窗（B4 反转）；审判者诅咒窗同总则——被非感应者伤害亮出 fleur-cross 开诅咒窗，被感应者封印则诅咒胜路当场作废（D1）。
- **技能一次性别（P3，推翻来源 C 原文两处）**：技能**已使用或已弃用后永不再开窗**；炼金治疗退回 rank、之后重新亮出 rank 也不能再次发动。炼金（rank 4）技能效果只有治疗（退 token）与 1 点伤害，不附带任何技能复活。来源 C 的「若退回 rank，之后重新展示 rank 时可再次使用能力」（rank 4 行与 `skill.reveal-rank` 待验收同义句）作废。
- **审判者被捕获 = 审判者独赢（P2，改引擎）**：采语料两处原文，推翻引擎的平局实现（无 ADR 记录的静默偏离）。对局形态：审判者可刻意暴露求捕（钓捕），家族猎杀前须确认目标身份。
- **盾只挡"被指定为目标"（P5，改引擎）**：删除"持盾者自己不能发动反伤"的引擎检查——持盾狂战士可正常反伤；攻击者持盾时拦截反伤（有规则出处）保留。盾不给持有者任何未写明的行动限制。
- **单人窗口超时兜底（P6 + L4，新增）**：见新规则行 `window.single-timeout`。要点：全程自动确定性默认、不用房主代行；技能窗超时 = 视为放弃（即弃用、永久失去）；单一房主配置、三类窗口共用、默认 90 秒。
- **wild 身份标记含问号（L4a 修正，语义扩展）**：审判者万能标记亮出时可自选玫/兽/**问号**三选（原语料只写玫/兽）；窗口超时默认问号。实现已另行开单。
- **法师法杖 × 审判者 wild（B9，维持引擎）**：法杖把审判者 wild 标记变普通问号、自选色永久丧失——字面执行且作为家族对抗审判者的手段，有意保留。
- **批量确认（21 条）**：A5/A6（第 3 点被迫 rank、第 4 点捕获不亮牌）、B1/B2（盾挡指定三源统一拦截、盾不挡自愿承伤）、B6（长老羽毛改数字最大、终局时点领袖）、B7（守护者 3 伤归还剑盾含技能/反伤源）、B8（法师改写含已亮标记）、B10（扇只挡投票、可给自己）、B11（小丑透视仅自己可见）、B12（技能后匕首移交受害者）、B13（技能误捕非领袖 = 技能方阵营负）、C1（rank 已亮者永无挡刀资格）、C2（"3 伤志愿者替审判者挡刀送敌胜"经 C1 推论**不可达**，留一致性注记）、D2（诅咒可发自己 = 浪费）、D3（真诅咒按终局时点领袖）、D5（误捕攻击方阵营负）、D6（捕获归因链）均按引擎现状确认为共识。
- **术语约定**：`game.end` 中的 "active player" 在中文表述中一律写作「**捕获归因**」（致伤者归属），避免与匕首持有者/行动阶段撞名：攻击 = 攻击者、挡刀 = 原攻击者、技能 = 使用者、反伤 = 狂战士。

## 暂定验收场景

以下场景只覆盖两份来源一致的核心规则。`Given` 中的角色/标记均为测试 fixture 的规则 ID，不要求复制原作显示文本。

### `setup/even-player-factions`

Given 8 名玩家和确定性随机源  
When 创建基础对局  
Then 红、蓝阵营各发出 4 张不重复身份，恰有一名玩家持有匕首，且每个玩家的左邻已获得其表象阵营投影。

### `setup/odd-player-inquisitor`

Given 7 名玩家和已提供的诅咒卡数量配置  
When 创建审判者对局  
Then Rose 与 Beast 各发出 3 张不重复身份，并从两张审判者中随机发出 1 张；准备 1 张诅咒卡与 fleur cross rank token。

### `turn/pass-dagger`

Given A 持有匕首且对局未结束  
When A 向 B 传递匕首  
Then 只产生传递事件，B 成为下一位可行动者，任何玩家均不失去生命或展示新线索。

### `combat/attack-handoff`

Given A 持有匕首，B 尚未展示任何线索且未请求干涉  
When A 攻击 B  
Then B 成为匕首持有者、受到 1 点伤害，并从尚未展示的线索中展示恰好一张。

### `combat/third-and-fourth-damage`

Given B 已展示两张线索且累计受到 2 点伤害  
When B 再受到 1 点可结算的伤害  
Then B 的三张线索均公开而 B 仍存活。  
When B 随后受到第 4 点伤害  
Then 对局立即结束，不再接受任何传递、攻击或技能命令。

### `intervention/selected-responder`

Given A 攻击 B，B 请求干涉，C 和 D 的 rank token 均仍在供应区  
When B 选择 C  
Then C 接过匕首并承受该点伤害，且 C 必须展示等级线索；B 不承受该点伤害，D 不受影响。

### `intervention/refused`

Given A 攻击 B，B 请求干涉且有至少一名响应者  
When B 拒绝全部响应  
Then B 接过匕首并承受该点伤害；该攻击中不再开启第二次干涉。

### `skill/reveal-rank-from-attack`

Given B 因攻击伤害选择或被要求展示等级线索，且其技能可用  
When 伤害展示结算完成  
Then 立即产生唯一一次该身份的可选技能窗口；任何由该技能造成的伤害均不创建新的干涉或技能窗口。

### `game/end-on-leader`

Given X 的阵营领袖仍为最小等级身份，active player A 属于敌对阵营，且 X 已受 3 点伤害  
When X 受到第 4 点伤害而被捕获  
Then A 的阵营获胜，并附带“active player 捕获敌方领袖”的可解释结果。

### `game/end-inquisitor-true-curse`

Given 正常家族胜方已经确定，且该胜方当前领袖持有 True Curse  
When 公开诅咒卡  
Then 审判者独赢，家族胜利被覆盖。

### `game/end-inquisitor-active-capture`

Given 审判者是 active player，目标玩家已受 3 点伤害  
When 审判者的攻击造成目标第 4 点伤害并使其被捕获  
Then 审判者按独立分支判负，其他方按该分支获胜。
