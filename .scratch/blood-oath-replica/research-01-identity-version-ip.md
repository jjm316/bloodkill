## 用户提供规则摘录的结构化摘要

- **设置**：6–12 人。偶数局移除两张审判官，从 Rose/Beast 各随机选取玩家数一半的身份；奇数局从 Rose/Beast 各选取人数向下取整的一半，并从两张审判官中随机选取一张。每人向左侧玩家展示 clue icon；匕首随机交给一人。7/9/11 人局各放置 1 张诅咒卡。
- **主循环**：匕首持有者可把匕首交给任一玩家，或攻击任一玩家；攻击后匕首交给目标。重复至有人死亡。
- **伤害与信息**：每点伤害从供应区拿取一个与角色三枚线索之一匹配且该图标尚未展示的 token；第 4 点被捕获并立即结束。不能拿取错误 token 欺骗；审判官的 wild affiliation icon 是例外。
- **干涉**：攻击目标可请求干涉；rank token 仍在供应区的玩家可响应；目标选择一名响应者或拒绝全部响应。干涉者必须展示 rank token，随后成为 active player。技能造成的伤害不能请求干涉。
- **技能窗口**：玩家在攻击中（作为目标或干涉者）拿取 rank token 后可立即发动能力；强制受伤的能力不算攻击。
- **阵营与胜负**：每个家族最小等级为领袖。第 4 点伤害使玩家被捕获；按当时 active player 是否捕获敌方领袖判定家族胜负。审判官若被捕获独赢，或在正常胜方领袖处放置 True Curse 时夺取独胜。
- **身份与标识物**：规则书正文确认长老羽毛使最高等级成为领袖；炼金治疗退回一个 token，若退回 rank 可再次发动能力；护卫盾禁止攻击/强制受伤但允许干涉，持剑护卫第 3 点伤害时解除匹配剑盾；法师使自己和目标各得法杖，持杖者展示 affiliation 时必须展示 unknown；交际花扇禁止他人干涉。实现时应用原创显示文案和资源，规则 ID 与显示内容分离。

## 待裁决的歧义与冲突

- **审判官诅咒数量**：产品方裁决 7/9/11 人局各放置 1 张诅咒卡；引擎应将该数量作为版本化 setup 数据。
- **审判官裁决**：两张审判官仅 clue icon 不同，共用 fleur cross rank token；审判官作为 active player 造成第 4 点伤害时独立判负，其他方获胜。
- **规则页可读性**：用户提供的网页与粘贴摘录可能来自同一来源，但页面目前无法独立读取；任何未来差异均记录为来源冲突并交由产品方裁决。

## 实施与 IP 决策（在身份确认前）

- 只实现与产品无关的可替换规则引擎骨架、事件日志、seed 和占位数据管线；不要写入具体牌名、角色名、数值、图示或规则书原文。
- UI 使用原创名称、图形和文案；浏览器客户端只通过用户本地启动的权威服务端提交命令。不得抓取或重绘官方插画、Logo、版图、扫描件或卡牌文本。
- 对外描述只能说“规则行为兼容的个人研究原型（目标版本待确认）”，不能宣称是某出版物的数字版或获得授权。
- 后续 `02` 规则语料票据在本票据解除前只能建立采集模板和待确认项，不得把网上转述当作规范。

## 非目标/暂缓项

在版本和授权确认前，暂缓任何不可逆的具体数值、牌组、地图、胜利条件、扩展内容、官方素材导入，以及商用发行或平台上架承诺。项目规格已经把在线匹配、账号体系、跨设备同步和高强度 AI 列为首版不包含项（见[规格](spec.md) MVP boundary）。
