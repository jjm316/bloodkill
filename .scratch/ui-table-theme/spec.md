## Problem Statement

（从玩家视角描述）这是个以"围桌"为核心体验的游戏：徽记要展示给左邻、匕首沿座位传递，但屏幕上的玩家卡片只是从左到右排两行，"我的左邻是谁"要靠数名字；桌面端大片空白，完全没有围桌感。整体观感是一套中性灰蓝的管理后台：没有品牌色、标题就是一行加粗系统字，跟"鲜血盟约"的哥特吸血鬼题材毫无关系。图标用的是 emoji，匕首、盾牌、剑在不同手机上长得不一样，个别 Windows 字体下还是方框。

## Solution

桌面端（≥720px）把座位沿一张纯 CSS 绘制的椭圆桌排布（深绯红渐变桌面 + 金描边）：自己的座位固定在正下方，按顺时针一眼看出左邻右舍，匕首在高亮座位间的移动有了空间意义；窄屏维持网格。配色收敛为主题变量：深底之上以"绯红（品牌/伤害/警示）+ 金（匕首/等级/高亮）"双强调色驱动全局；标题与横幅用本地中文衬线字体栈（零下载）；背景加纯 CSS 渐晕营造烛光桌面氛围。匕首/盾/剑/杖/扇/锁/羽毛笔 7 个图标替换为内联 SVG 线性图标。纯前端、零协议改动、零新依赖、无图片资源。

## User Stories

1. As a 桌面玩家, I want 座位沿一张椭圆桌排布、按座位顺序相邻, so that 徽记展示和匕首传递的"左邻"关系一眼可见。
2. As a 桌面玩家, I want 自己的座位始终位于桌面正下方, so that "我的左邻在左侧"成为稳定的方位直觉。
3. As a 桌面玩家, I want 匕首持有者的高亮座位在桌面上位置醒目, so that 我能追踪刀在桌上如何流动。
4. As a 桌面玩家, I want 待办横幅（投票/亮牌/技能）出现在桌面中心区域, so that 视线焦点自然落在"桌中央"。
5. As a 玩家, I want 界面以深色烛光氛围呈现：渐晕背景、绯红与金的双强调色, so that 它看起来像一款哥特桌游而不是后台系统。
6. As a 玩家, I want "鲜血盟约"标题与各页大标题使用中文衬线字体, so that 有桌游的仪式感。
7. As a 大陆玩家, I want 字体全部来自本地字体栈、不发起任何外部字体下载, so that 首屏速度不受影响也不会加载失败。
8. As a 玩家, I want 匕首、盾牌、剑、法杖、扇子、锁等图标在所有设备上渲染一致, so that 信息不因平台差异而误读。
9. As a 色弱玩家, I want 玫瑰/野兽标记除颜色外仍保留"玫/兽"文字, so that 红蓝不构成唯一信息通道。
10. As a 玩家, I want 新配色的正文与界面文字对比度不低于现状（≥4.5:1）, so that 可读性不回退。
11. As a 手机玩家, I want 窄屏下座位保持网格排列（不强行上圆桌）, so that 小屏信息密度可控。
12. As a 键盘用户, I want 绝对定位的座位不破坏 Tab 顺序与焦点环, so that 键盘操作仍然可用。
13. As a 开启"减少动态效果"的玩家, I want 本轮不新增任何动画, so that 我的系统偏好继续被尊重。
14. As a 回放观看者, I want 回放屏与对局屏共用同一桌面布局, so that 复盘与实战的空间记忆一致。
15. As a 12 人局的玩家, I want 满员时座位间距仍然可辨、卡片不重叠, so that 大局不拥挤。
16. As a 玩家, I want 被捕获座位的划线弱化、离线提示保持现有语义, so that 状态阅读习惯不变。
17. As a 玩家, I want 大厅与等待房与对局共用同一套色彩与标题风格, so that 全程观感统一。
18. As a 玩家, I want 备忘徽章与线索槽的既有配色语义（玫红/兽蓝/灰）保持, so that 已养成的阅读习惯不被推翻。
19. As a 开发者, I want 座位坐标计算是一个与组件分离的纯函数, so that 可以直接单测、未来调桌形只改一处。
20. As a 开发者, I want 现有样式里硬编码的颜色值收敛为 CSS 变量后再引入新色, so that 主题调整有单一出处、不做一次性替换。
21. As a 开发者, I want 包体增量可忽略（无图片、无字体文件、SVG 内联）, so that 首屏性能不回退。

## Implementation Decisions

- **圆桌布局**：对局桌面区在 ≥720px 视口启用圆桌容器，容器本体绘制纯 CSS 椭圆桌形（深绯红径向渐变 + 金色描边 + 内阴影，零位图，造型以参考稿为准，2026-09-13 拍板）：座位卡片绝对定位在椭圆上，坐标由纯函数 `seatPosition(座位序号, 总人数) → {x%, y%}` 计算（独立纯模块，仿事件类别映射表的组织方式）。 viewer 自己的座位经索引偏移旋转到正下方（6 点位），其余按座位顺序顺时针排布；"左邻"即数组前驱，不新增任何服务端字段。座位数 6–12 时半径/间距用同一公式自适应。窄屏（<720px）不启用圆桌，沿用第一批的网格。
- **待办横幅位置**：Board 的投票/亮牌/技能横幅（.pending）渲染在桌面容器中心（绝对定位居中），移动端回到文档流顶部；GameScreen 的干涉等待横幅（.waiting-banner，含倒计时）不进桌心、留在文档流不动，桌心化留给第三批横幅合并（2026-09-13 拍板）。
- **主题变量**：styles.css 顶部建立 `--bg / --card / --border / --text / --muted / --accent-gold / --accent-crimson / --danger` 等变量，现有硬编码色值全部改为引用变量（含事件日志的 6 个 `--cat-*` 类别色）；金继续承担匕首/等级/高亮语义，绯红承担品牌标识/伤害/警示/倒计时紧迫语义。配色方向已锁定（2026-09-13）：参考稿的紫红黑底（--bg #0e0709 系、--card #1f1219、--border #4b2e3a、--text #f2e7ea、--muted #b9a3ac），金沿用 #f5c518 / #f0c060，装饰绯红 #8e1f2f，danger 沿用 #ff8a80；实现时经对比度校验（正文 ≥4.5:1）可微调色值，不需再过 grill。
- **标题字体**：标题与大横幅使用本地栈 `"Noto Serif SC", "Source Han Serif SC", STZhongsong, KaiTi, serif`；正文与控件维持系统字（中文正文用衬线可读性差，不全局替换）。
- **背景氛围**：body 增加径向渐晕（中央略亮、四角压暗），可选叠加极淡的纯 CSS 纹理；不引入任何位图。
- **图标**：建立内联 SVG 图标集（匕首、盾、剑、杖、扇、锁、羽毛笔，共 7 个 = 5 资源 + 匕首 + 房间锁，全项目 emoji 仅此 7 处，2026-09-13 盘点更正；线性 stroke 风格，`currentColor` 着色），替换资源图标映射、座位匕首、房间锁三处 emoji；不引第三方图标库。玫瑰/野兽/未知标记维持"字 + 色块"现状（兼顾色弱与辨识成本）。
- **遵循 ADR 0004 的 client-only 原则**：本 spec 零服务端、零协议改动；改动范围仅 client/src（样式层、Board 布局、图标组件）。
- 明确不做：亮/暗双主题切换、logo 重绘、任何位图美术资源、移动端圆桌。

## Testing Decisions

- 好的测试只测外部行为；布局观感无法也不应在 jsdom 里断言，单测只覆盖可提取的纯逻辑。
- **座位坐标纯函数**：vitest 单测——N 人等分角度正确、viewer 落在正下方、6 人与 12 人两档无坐标重叠（先例：eventLog.test.ts 对纯数据映射的测法）。
- **图标**：渲染 smoke 测试（图标组件输出 svg 且带预期 aria-hidden），不逐个断言路径数据。
- **视觉验收**：无头 Chrome 截图对照——1440×900 八人圆桌（自身在下、左邻方位正确、横幅居中）、390×844 网格与第一批基线一致无回归；对比度用脚本抽查主要文字/背景组合 ≥4.5:1。
- 主题变量重构以"全局视觉回归截图 + 现有 vitest 全绿"兜底，不为变量改名写专项测试。

## Out of Scope

- 一切动效与状态反馈（横幅合并、倒计时紧迫态、受伤脉冲等，第三批 Spec C）。
- 移动端圆桌、可拖拽/自旋转桌面、双主题、美术级原画资源。
- 服务端与协议的任何改动。

## Further Notes

- 本 spec 视觉方向已经 2026-09-12 评估确认（规则库给出的桌游类基准同为"深底 + 强对比强调色"）；2026-09-13 grill 拍板四项并回写正文：①画椭圆桌形本体 ②图标 7 个（"8 个"系笔误）③waiting-banner 不进桌心 ④配色走参考稿紫红黑方向。色值以参考稿为起点、实现时按对比度校验微调即可。

### 2026-09-13 移动端座位散架修复（bat 平铺窗口实测暴露）

- **现象**：`测试工具箱-开新局.bat`（7 人 4 列平铺，4K@150% 下每窗视口约 624×580）开局后座位卡片散乱、互相重叠、被窗口右缘裁切；≥720px 视口正常。
- **根因**：Board 给每个座位无条件注入内联 `left/top` 百分比；窄屏网格分支的 `.seat` 是 `position: relative`（备忘角标定位锚），relative 定位下 left/top 不是"定位到"而是"从网格单元格平移"（百分比按网格区域解析），卡片被逐个平移出格。
- **修复**：坐标改以 CSS 变量 `--seat-x/--seat-y` 注入，仅 ≥720px 圆桌分支的 CSS 消费（`left: var(--seat-x)`），网格分支完全不感知。实测 624×580 恢复整齐网格、1440 圆桌几何不变（self 居中正下方、零重叠）。
- **回归防护**：`boardLayout.test.tsx` 钉死注入契约——座位不得携带内联 left/top、必须携带 --seat-x/--seat-y、self 座位 y 为最大（6 点位）。
- **验收教训**：首批视觉验收在 <720px 只截了图没量座位矩形（视觉判定把轻度平移读成"整齐"），≥720px 才做了坐标测量——断点两侧行为不同，两侧都要量 DOM 矩形。
