Blocked by: None（可立即开始）

## 要交付的行为

玩家创建房间失败时，前端对「这条消息来自服务端还是本地异常」的判定从「嗅探消息里是否含中文字符」改为结构化错误类型：解析到服务端错误帧时抛携带错误码的结构化错误，catch 按类型分流——结构化错误原文展示服务端中文消息，网络失败等其他异常显示既有本地兜底文案。两分支的最终文案与现状完全一致，只换判定机制。

## 前置依赖

无。

## 验收条件

- [x] 客户端不再存在按 CJK 字符范围嗅探错误消息来源的正则；创建房间的 catch 按错误类型分流。
- [x] 结构化错误类型携带服务端错误帧的错误码与消息，定义在现有 API 调用所在模块，不新建抽象层。
- [x] 服务端错误消息含非中文字符时仍会原文展示（嗅探时代会误吞，这是被修复的缺陷面）；网络失败（非结构化异常）显示本地兜底文案「创建房间失败，请查询已有房间或重试。」。
- [x] 新增 vitest 用例：服务端错误帧原文展示；非结构化异常显示兜底文案。
- [x] 其余 fetch 调用点不在本票迁移范围内；`npm test --prefix client` 与 `python scripts/check.py` 通过。
