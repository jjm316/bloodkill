# 技能耦合测试补强：B7 / B9 / C2 一致性锁

Status: resolved（2026-10-04 实现，commit b19e59e；断血验证与两处实现记录见末尾 Comments）

对应规则耦合评审（`.scratch/rule-coupling-review/`，30 卡，基线 ruleset 0.5 @ c522262）覆盖复核的结论：绝大多数耦合点已有行为级专项测试，仅三处见证薄弱。本 spec 只补测试，不改引擎、投影、客户端与规则语料。

## Problem Statement

规则耦合评审后，三处已裁决的耦合语义缺少可靠的机器见证：

1. **B7 守护者「3 伤归还剑盾，跨所有伤害来源」**——语料批量确认明确写了"含技能/反伤源"，帮助文案也向玩家承诺"无论这 3 点来自攻击、挡刀、技能伤害还是狂战士反伤"，但唯一的专项测试是白盒：手工把守护者伤害置 3、直调引擎私有结算函数。四种来源没有一种经过真实命令验证。
2. **B9 法师×审判者万能标记**——语料第 87 行裁决"维持引擎：法杖把审判者 wild 标记变普通问号、自选色永久丧失，有意保留"，引擎行为与裁决一致，但零测试。将来任何人重构法师实现，都没有护栏拦住语义漂移。
3. **C2「3 伤志愿者替审判者挡刀送敌胜」**——语料裁决为"经 C1 推论**不可达**，留一致性注记"：3 伤 ⇒ 第 3 点必亮 rank（A5）⇒ rank 已亮者永无挡刀资格（C1）⇒ 自杀分支不可达。但这条三段论推论本身没有机器验证——将来若有人放宽强制亮牌或挡刀资格规则，"义挡变投敌"的分支会悄悄复活且无测试报警。

## Solution

补三组行为级测试，全部走既有公开命令接缝：

- **B7**：重写守护者归还测试，攻击 / 挡刀 / 技能伤害 / 狂战士反伤四个场景各自从真实命令序列把守护者打到第 3 点，断言剑与盾同时归还、且后续伤害不重复归还；删除直调私有函数的白盒测试。
- **B9**：按「未亮 wild / 已亮自选色 wild」两档矩阵锁死法师抹除语义——未亮的被抹后经伤害亮出时不再开色选窗、直接亮出问号；已亮的公开值被改写为问号（公开情报抹除，B8 语义）；并断言抹除后自选色永久丧失。
- **C2**：把不可达推论拆成两条机器化注记——(a) "任何 3 伤玩家 rank 必已亮"进性质测试的共享不变量断言（随机 walk 每条命令后全程验证）；(b) "rank 已亮者不出现在干涉志愿者名单"进技能分支测试类的专项断言。

## User Stories

1. As an 引擎维护者, I want 守护者 3 伤归还剑盾在攻击、挡刀、技能伤害、狂战士反伤四种真实来源下各有一条行为测试, so that 重构伤害结算管线时任何一条来源的回归都会被拦下，而不是只有结构上"殊途同归"的口头保证。
2. As an 引擎维护者, I want 白盒直调私有结算函数的守护者测试被真实命令驱动的测试替换, so that 测试见证的是引擎对外承诺的行为而非内部实现细节，未来重构内部管线不必同步改测试。
3. As an 引擎维护者, I want 法师抹除审判者 wild 标记后的完整语义（标记变问号、色选窗不再出现、已公开的色值被改写、自选权永久丧失）被一组测试锁定, so that 重构法师技能时裁决语义不会漂移。
4. As an 规则产品方, I want 语料第 87 行 B9 裁决（"字面执行且作为家族对抗审判者的手段，有意保留"）至少有一个机器见证, so that 每条已裁决的耦合点都有测试对应，评审记录与测试库一一印证。
5. As an 引擎维护者, I want "伤害等于 3 的玩家 rank 必已亮"作为全局不变量在每条命令后验证, so that 将来改动第 3 点强制亮牌规则（A5）时，所有依赖该推论的下游结论（含 C2 不可达）立刻有测试报警。
6. As an 引擎维护者, I want "rank 已亮者不出现在干涉志愿者合格名单"有专项断言, so that 将来改动挡刀资格规则（C1）时同样立刻报警。
7. As an 规则作者, I want "3 伤者不可能挡刀自杀送敌胜"这条规则书注记由两条独立测试共同机器化, so that 注记不是纸面推论而是可回归验证的事实。
8. As an 引擎维护者, I want 已亮 wild 被法师抹除后公开值改写为问号的行为被断言, so that B8「公开情报改写」裁决与 B9 裁决的交叉面也有见证。
9. As an 未来实现 agent, I want 本 spec 明确"纯测试、引擎现状即预期"的边界, so that 实现时若发现引擎与语料裁决不符，能立即停下按先报后修流程回报，而不是顺手改引擎或改测试期望。
10. As an 测试跑者, I want 全部新测试并入现有 unittest discover 套件且不需要新依赖, so that `python -m unittest discover` 一条命令照常全量验证。
11. As an golden 基线守护者, I want 法师抹除/守护者归还若已被现有 golden 对局覆盖则顺手挂上分支覆盖锁，若未覆盖则明确跳过, so that 分支锁清单与事实一致，且不为一条锁重新生成全量 golden 基准。

## Implementation Decisions

- **零引擎改动**。本 spec 的预期行为全部等于引擎现状 + 语料裁决；任何一条测试写出来挂了，说明引擎与裁决不符，按仓库"先报现状等拍板再修"惯例停下回报，另开 fix 单，不得在测试里发明规则、也不得顺手改引擎。
- **B7 四来源场景设计**：守护者先经正常技能窗给某玩家放盾（自己持剑）、自己先积累 2 点真实伤害，然后分别经 (a) 普通攻击 (b) 以志愿者身份替他人挡刀（干涉承伤）(c) 感应者技能伤害 (d) 攻击狂战士被反伤，承受第 3 点。每个场景断言：剑与盾各一条归还事件、双方资源归零、之后再受伤不重复归还。状态一律由命令序列产生（用既有测试的应答助手逐窗走完），不手工改伤害字段。
- **B9 两档矩阵**：(a) 审判者两张 wild 均未亮——法师对其用技能后，两张身份标记变问号；此后该标记经伤害亮出时不再出现 wild 色选三选项（玫/兽/问号窗不复存在），直接以问号值亮出。(b) 审判者已亮一张 wild 并自选了色——法师抹除后该已公开值改写为问号。两档都要断言抹除事件与法杖资源发放。
- **C2 两条机器化注记**：(a) 共享不变量断言函数追加"任意存活玩家伤害为 3 ⇒ rank 在已亮集合中"——这同时锁 A5 第 3 点强制亮牌推论；(b) 技能分支测试类新增专项：构造 rank 已亮玩家，断言其不在攻击后干涉窗的合格志愿者名单中。
- **golden 分支锁（可选步骤）**：实现时先检查现有 golden 对局（6–12 人七份基准）是否已含法师抹除事件 / 守护者归还事件；已含则按现有分支锁类的模式各补一条"some golden …"断言；未含则跳过并在实现记录中注明"现有基准未路过该分支，专项单测是唯一见证人"。不为加锁重生成 golden（ruleset 0.5 fixtures 是全量基准）。
- **测试落点**：B7/B9/C2(b) 并入现有技能分支测试类（共享其开局/应答/给匕首助手），C2(a) 并入性质测试的共享不变量断言函数（全部 walk 场景自动获得）。不新建测试模块。

## Testing Decisions

- **好测试的标准**：只经公开命令接缝驱动（apply 命令 + legal_actions 断言），事件流断言用事件类型与 payload；被测状态必须由命令序列产生（技能窗用既有测试惯用的正常发动路径打开，不用私有方法注入 pending、不手改 damage/resources）。引擎公开返回的 state 字段（伤害、资源、已亮集合）可按既有测试风格直接读。
- **被测模块**：引擎技能结算与伤害结算（B7/B9）、干涉合格名单计算（C2b）、全机制状态不变量（C2a）。
- **既有范式（prior art）**：技能分支测试类中灵媒封印三方连锁测试（多技能真实命令串联）、炼金 harm 盾过滤测试（affordance + 引擎拒绝双断言）、性质测试的共享不变量断言函数、golden 分支覆盖锁类的"some golden"系列。
- **跑法**：仓库 `.venv` 的 `python -m unittest discover -v`（未装 pytest，不装）。
- **验收**：全量测试绿；新测试在故意注入回归（如临时删掉归还逻辑/抹除改写）时会红——实现 agent 应做一次这种"断血验证"再交付。

## Out of Scope

- 任何引擎、投影、客户端行为改动（若测试暴露引擎与裁决不符，另开 fix 单处理）。
- 帮助文案与 CONTEXT.md 的「不可达注记」补充（E1 批次已收口，是否补注记由产品另定）。
- golden fixtures 重生成或确定性 runner 改动。
- wild 色选三选项（玫/兽/问号）本身的行为（issue 26 已有专项与分支锁）。
- 其余 25 个已有专项或不变量见证的耦合点。

## Comments

- 2026-10-04 实现并全量绿（commit b19e59e，192 tests OK，引擎零改动）。B7 白盒测试已删除，替换为四条真实命令驱动的场景测试（普通攻击 / 志愿挡刀 / 感应者技能 / 狂战士反伤），共用新增的 `attack_wound` / `arm_guardian_ward` / `assert_ward_returned` / `capture_at_three_damage` 助手；每条断言剑盾各一条 `ResourceReturned`（含 reason 与顺序）、双方资源归零、第 4 点捕获不再归还。B9 两档矩阵各一条：未亮档断言抹除事件 + 法杖发放 + 标记变问号 + 后续亮牌窗无色选三选项（issue 26 的玫/兽/问号窗不复存在）；已亮档断言公开值改写为问号（B8 交叉面）且幸存 wild 同样失去色选窗。C2(b) 专项断言 rank 已亮者不在干涉志愿者名单且无任何 legal action；C2(a)「伤害=3 ⇒ rank 已亮」进 `test_properties.assert_state_invariants`，全部 walk 每条命令后全程验证。
- 挡刀场景与 spec 草图的偏差说明：C1（rank 已亮者永无挡刀资格，即本 spec C2(b) 机器化的那条）使得「先用技能（rank 必亮）→ 攒 2 伤 → 再志愿挡刀」按字面不可达。实现走唯一合法通路：守护者先亮 rank 开技能窗（持剑、放盾、攒 2 伤），炼金术师干涉挡下第 3 刀并治疗退回守护者的 rank token（同时退 1 点伤），守护者补 1 伤后以 2 伤、rank 未亮身份志愿承伤吃第 3 点——全程公开命令，引擎行为与语料 C1/B7 裁决一致，无需另开 fix 单。
- golden 分支锁：跳过。6–12 人七份基准均未路过 `IdentityMarkersObscured` 或 `ResourceReturned`（grep 零命中），不为一条锁重生成全量基准——现有 golden 未覆盖这两分支，专项单测是唯一见证人。
- 断血验证四连（各注入回归、确认变红、再还原）：删归还逻辑 → B7 四条全红；抹除变异改 pass → B9 两档全红；干涉资格去掉 rank 未亮过滤 → C2(b) 红；wound 停止亮牌（`_continue_damage` 提前 settle）→ C2(a) 性质不变量红。还原后全量 192 tests OK。
- 实现中发现的结构事实：damage 3 ⇒ rank 已亮由 token 经济结构性保证——每次 wound 恰好净亮 1 个 token、退 token 必同时退 1 点伤，而 marker 只有 2 张，故第 3 点的 reveal 事件必落在 rank 上。不变量锁的是该结构被未来改动破坏的情形（例如亮牌与扣血解耦、或 wound 不再伴随 reveal），而非当前引擎可能出错。
