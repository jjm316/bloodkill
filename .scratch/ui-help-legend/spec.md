# 教学/图例：大厅"怎么玩" + 规则浮层（等级技能表与标记图例）

Type: task
Status: resolved
来源: 从 wontfix 的 `.scratch/ui-polish/spec.md` 拆出（其 Comments 已回填指针），原 User Story 17–19 的"怎么玩/规则浮层"扩展为本 spec
验收基准: 原型 `.scratch/ui-help-legend/legend-scope-prototype.html`（`?variant=compact` 为拍板版，图标与配色逐字复刻现有实现）；手机 375px 档必须无头截图实测

## Problem Statement

（从玩家视角描述）第一次点开链接的朋友完全不懂规则：不知道徽记是干什么的，亮等级开了技能窗口不知道自己能做什么选择，线索槽里的红蓝字块看不懂，看到匕首、盾、扇子这些图标不知道意味着什么——没人解释，只能边玩边猜。被扇子挡了挡刀机会、不能攻击持盾的人、有人亮出来是"？"，全都不知道为什么。奇数局抽到审判者更是两眼一抹黑，连诅咒该不该分发都不明白。

## Solution

大厅加可折叠的"怎么玩"五句话简介；对局页（等待房与对局中、含旁观视图）页头加"？"按钮打开"规则与图例"浮层。浮层三个分区：怎么玩简介、等级技能表（等级 1–9 + 审判者，每行等级数字 + 角色名 + 该等级的线索标记组成 + 1–2 句完整效果）、标记图例（匕首 + 五资源各一行，线索标记与徽记压成两行短注）。两处共用同一份前端静态中文文案数据。浮层适配手机宽度、超一屏可竖向滚动。纯前端、零协议改动。

## User Stories

1. As a 第一次玩的新玩家, I want 大厅有一个可展开的"怎么玩"简介（五句话以内：徽记、攻击、挡刀、亮牌、胜负）, so that 开局前心里有数。
2. As a 读完简介的玩家, I want 简介末尾提示"点开帮助可查看九级技能与标记图例", so that 知道深度内容在哪里。
3. As a 等待房里的玩家, I want 页头"？"按钮随时打开规则浮层, so that 等开局的时间可以先把规则学了。
4. As a 对局中的玩家, I want 页头"？"按钮随时打开规则浮层, so that 遇到不懂的术语和图标随时查。
5. As a 亮等级开启技能窗口的玩家, I want 浮层里有一张等级 1–9 加审判者的技能表, so that 知道自己的技能该做什么选择、别人的技能意味着什么。
6. As a 新玩家, I want 等级表每行同时显示等级数字和角色名（长老/刺客/小丑/炼金术师/感应者/守护者/狂战士/法师/交际花）, so that 朋友间口语讨论的名字能对上号，拿名字也能搜到原版资料。
7. As a 读牌的玩家, I want 等级表每行附带该等级的线索标记组成（玫/兽/？色块）, so that 我能理解"为什么他亮出来是？"。
8. As a 奇数局的审判者, I want 等级表含审判者行（标注"仅奇数局"）说明诅咒分发技能, so that 第一次当审判者知道技能何时发动、真/假诅咒的后果是什么。
9. As a 持匕首的玩家, I want 图例第一条解释匕首是行动权的标志, so that 明白轮到自己时是传递还是攻击。
10. As a 想发起攻击的玩家, I want 图例解释护盾持有者不可被指定伤害, so that 明白为什么选不了那个目标。
11. As a 被攻击的玩家, I want 图例解释扇子持有者被攻击时无人可挡刀, so that 明白这次干涉表决为什么直接跳过。
12. As a 看到剑的玩家, I want 图例解释剑是守护技能的守护标记、目标 3 伤时与盾一同归还, so that 不把剑误当成攻击资源。
13. As a 被法杖遮蔽的玩家, I want 图例解释法杖会把身份标记遮成"？", so that 明白自己线索槽变化的原因。
14. As a 看到羽笔的玩家, I want 图例解释羽笔与领袖继承的关系, so that 理解长老技能对胜负判定的影响。
15. As a 看线索槽的玩家, I want 图例用缩小版三格槽示意解释"填亮几格 = 受了几点伤", so that 亮牌进度和伤害的关系不用猜。
16. As a 色弱的玩家, I want 线索标记沿用"字+色块"渲染而非纯色 SVG, so that 对颜色不敏感也能读牌。
17. As a 只看过右邻徽记的玩家, I want 图例说明徽记"只是线索不是事实"（小丑恒为敌对家族、审判者必然与其真实所属不符）, so that 不把开局看到的徽记当成铁证。
18. As a 使用备忘标记的玩家, I want 备忘角标维持在现有选择器内的说明而不进规则图例, so that 私有猜测与公共规则事实不混淆。
19. As a 手机玩家, I want 规则浮层适配手机宽度、内容超一屏可上下滚动, so that 小屏也能完整阅读。
20. As a 手机玩家, I want 大厅"怎么玩"折叠块在窄屏不横向溢出, so that 开局前在手机上也能读简介。
21. As a 打开浮层的玩家, I want Escape 与点击遮罩关闭浮层, so that 退出方式与既有弹窗一致。
22. As a 玩家, I want 大厅简介与房内浮层共用同一份文案数据, so that 两处说法永远一致不会改漏。
23. As a 玩家, I want 全部帮助内容是中文静态文案、随页面加载, so that 阅读零等待、断网也能查。
24. As a 旁观者, I want "？"按钮与规则浮层在旁观视图同样可用, so that 查房学规则与玩家一致。
25. As a 开发者, I want 本 issue 零服务端、零协议、零引擎改动, so that 存档、回放、规则版本不受影响。

## Implementation Decisions

- **文案单一来源**：新建 client 端一个纯静态中文数据模块（仿事件类别映射的组织方式），导出三部分：简介段落（intro）、等级技能表、标记图例条目。大厅折叠块只渲染 intro；浮层渲染全部。不新建任何协议字段或服务端接口（遵循 ADR 0004 的 client-only 原则）。
- **入口**：对局页头部加"？"圆形按钮开浮层——等待房与对局共用同一页面组件，按钮一处即可两阶段可用；旁观视图同组件自动继承。大厅加可折叠"怎么玩"块。
- **等级技能表**：10 行 = 等级 1–9 + 审判者（标注"仅奇数局"）。每行四元组：等级数字、角色名、标记组成色块、1–2 句效果文案。各行的规则事实底线（文案实现时按引擎事实定稿润色）：
  - 等级 1 · 长老：取得羽笔并立刻消耗，本家族领袖改由存活者中等级数字最大者担任；
  - 等级 2 · 刺客：指定一名玩家受 2 点伤害，匕首交给该玩家；
  - 等级 3 · 小丑：秘密检视两名玩家的身份；
  - 等级 4 · 炼金术师：仅在干涉时发动——使被保护者受 1 点伤害，或治疗 1 点伤害并令其退回一张已亮标记；
  - 等级 5 · 感应者：使一名玩家受 1 点伤害（迫其亮等级），匕首交给目标；
  - 等级 6 · 守护者：为目标放置护盾，剑由自己持有作为守护标记；目标累计 3 点伤害时剑与盾一同归还；
  - 等级 7 · 狂战士：被攻击或为挡刀承伤时，原攻击者承受 1 点反伤；
  - 等级 8 · 法师：授予法杖，目标的身份标记全部被遮蔽为"？"；
  - 等级 9 · 交际花：授予扇子——持有者被攻击时无人可志愿挡刀；
  - 审判者：亮出等级开启的技能窗口中，将真诅咒与假诅咒暗置分发给不同玩家，或放弃（放弃则诅咒留在供应区）。
  - 通用规则注释（至少一处提及）：技能造成的伤害不产生新的干涉或技能窗口。
- **角色名**：官方中文名（1 长老 / 2 刺客 / 3 小丑 / 4 炼金术师 / 5 感应者 / 6 守护者 / 7 狂战士 / 8 法师 / 9 交际花，审判者已有名）。角色名**仅存在于帮助浮层的静态文案**；对局实时显示（亮牌槽、技能横幅、事件日志）维持纯"等级N"——既有"角色名不进等级文案"裁决的范围照此收窄，相关代码内裁决注释同步改写。取舍记录见 ADR 0005。
- **标记组成列**：等级表每行附固定的等级→线索标记组合——1/5/6＝双同色、2/3/4＝双"？"、7/8/9＝一同色一"？"、审判者＝两张万能标记（亮出时自选玫/兽）。色块复用现有"字+色块"渲染，不新增 SVG。
- **标记图例**：道具区 6 条全量（匕首、羽笔、护盾、剑、法杖、扇子），每条一行 = 现有 SVG 图标 + 名称 + 1–2 句效果；道具**名称与对局内资源显示名统一**（羽毛笔/盾牌/剑/法杖/扇子——以现有客户端映射为准，不用后端 locale 的"羽笔/扇"）：图例的使命就是让玩家把图标、名字、效果对上号，不能自己制造第二套名字。"线索与徽记 — 读牌符号"小节压成 2 行短注：行 1 缩小版三格槽示意（`3｜玫｜？`）+ 填亮与伤害同步、玫/兽亮出才可见、"？"来源的一段话；行 2 玫/兽色块 + 徽记非事实说明。文案以原型 compact 版为底稿修订。
- **文案口径**：每条 1–2 句、玩家可执行完整度（触发时机 + 关键限制，如"持盾不可被指定""扇子跳过干涉表决"）；不直接搬运后端内容目录的占位文案（等级 2、审判者、全部资源描述均为开发占位）。intro 由 agent 按词表与引擎事实起草、用户在代码里审。
- **浮层形态**：单个模态浮层分三区（怎么玩 / 等级技能表 / 标记图例），复用现有模态样式与交互（Escape、点击遮罩关闭）；不做就地 tooltip。宽度比一般面板更宽、窄屏收缩，内容竖向可滚、任何视口不得横向溢出。
- **手机适配是验收硬门槛**：375px 档必须实测（无横向溢出、可竖滚）。
- 明确不做：音效、多语言、分步新手引导。

## Testing Decisions

- 好的测试只测外部行为：断言用户可见的渲染结果与可交互性，不测数据模块内部形状或 CSS 规则本身。
- **vitest + jsdom**（先例：`WaitingRoom.test.tsx`、`eventLog.test.tsx` 的渲染断言方式）：
  - 浮层开合：点"？"出现浮层，Escape 与遮罩点击均可关闭；
  - 等级表：渲染 10 行、审判者行含"仅奇数局"标注；
  - 图例：6 条道具条目与线索/徽记短注存在；
  - 大厅折叠块：展开后只见简介，不含等级表与图例（两处内容口径的回归锚点）。
- **数据防呆单测**：角色名映射与标记组成映射是纯数据，用静态期望表断言（9 个等级 + 审判者、名字非空、标记组合与引擎映射一致），防止实现时抄错行。
- **视觉/手机适配验收**：无头 Chrome 截图——桌面 1280×800 浮层全貌、手机 375px 档验证无横向溢出可竖滚；复用圆桌主题批次的截图配方与视口坑位。

- 服务端、协议、引擎的任何改动；后端内容目录占位文案的治理。
- ui-polish 其余三项（横幅合并与紧迫态、复制分享、名册卡片化、动效）——维持 wontfix。
