# 审判者诅咒分发改为亮等级技能窗口（含真假标注与攻击过滤）

Type: task
Status: resolved（2026-09-05 实现，commit f80018d，ruleset 0.4；收尾记录见本文件末尾 Comments）
ADR: docs/adr/0003-inquisitor-curse-as-reveal-triggered-skill.md
裁决日期: 2026-09-05（产品方 grilling 裁决）

## Problem Statement

（以下从玩家视角描述）审判者在整局对局中随时都能看到"秘密将诅咒牌交给"的分发面板——它从开局就常驻在动作区，与"角色能力应在特定时机发动"的全桌体验相悖：其他玩家的技能都要靠受伤亮等级换取，审判者的胜负手却可以任意拖延、憋到残局再发。而且分发界面的两个下拉框没有任何标注，审判者分不清哪一张选的是真诅咒、哪一张是假诅咒，"暗置分发"这一核心操作根本无法可靠执行。另外，审判者不能攻击已受 3 点伤害玩家的限制只能在点击按钮收到报错后才知道。

## Solution

诅咒分发成为审判者的正式技能，与 rank 1–9 角色技能同一套流程：因攻击或挡刀伤害亮出等级（fleur-cross）时开启唯一一次技能窗口，审判者在窗口中选择发动或放弃。发动时分发界面明确标注「真诅咒交给：」「假诅咒交给：」，提交前弹确认框说明"分发后不可更改，归属对其他玩家永远保密"。放弃（或从未亮出等级）则诅咒永远留在供应区、诅咒胜路作废。同时审判者的攻击按钮过滤掉已受 3 点伤害的目标。旧的全时段常驻分发入口整体移除。

## User Stories

1. As a 审判者玩家, I want 诅咒分发只在我因攻击或挡刀伤害亮出等级时以技能窗口的形式开启, so that 使用能力的方式与其他角色技能完全一致，无法任意拖延憋招。
2. As a 审判者玩家, I want 技能窗口内同时提供「发动能力：分发诅咒牌」与「放弃技能」两个动作, so that 我拥有与其他技能相同的一次性发动/放弃决定权。
3. As a 审判者玩家, I want 动作区内先只显示一个发动按钮、点开后才展开选择界面, so that 选择界面只在我决定发动后才出现，避免误触。
4. As a 审判者玩家, I want 两个下拉框分别标注「真诅咒交给：」「假诅咒交给：」, so that 我能可靠决定哪张卡给谁。
5. As a 审判者玩家, I want 提交前看到确认弹窗，写明分发后不可更改且归属对其他玩家永远保密, so that 这个不可逆的私密操作有防手滑确认。
6. As a 审判者玩家, I want 两张卡都选定收件人之前确认按钮保持禁用, so that 我不会提交不完整的分配。
7. As a 审判者玩家, I want 收件人列表不包含我自己, so that 我不会不小心把诅咒分给自己。
8. As a 审判者玩家, I want 放弃技能后窗口永久关闭、诅咒留在供应区, so that 放弃是一个真实、不可撤销的取舍。
9. As a 审判者玩家, I want 无论主动亮等级（第 1/2 点伤害自选）、第 3 点被迫亮等级、还是挡刀被迫亮等级，都同样开启窗口, so that 所有亮等级路径行为一致。
10. As a 审判者玩家, I want 已发动或放弃后不再出现第二次窗口, so that 技能的唯一性不被破坏。
11. As a 审判者玩家, I want 攻击按钮不再显示已受 3 点伤害的玩家, so that 我的限制在界面上就可见，而不是点击后才报错。
12. As a 审判者玩家, I want 我亮出的等级公开展示为「审判者」, so that 这是可读的公开事实（与实体游戏的 fleur cross 等级标记一致）。
13. As an 其他玩家, I want 审判者的技能窗口开启时看到公开横幅, so that 我知道他的能力已经进场——但看不到他分给了谁。
14. As an 其他玩家, I want 诅咒归属在任何状态、事件与日志中都对我不可见, so that 直到终局判定为止秘密成立。
15. As an 观众, I want 投影中完全不含诅咒归属, so that 旁观不泄露任何秘密。
16. As a 房主, I want 奇数局开局的诅咒生成与人数规则保持不变, so that 开局流程与其他版本体验一致。
17. As a 开发者, I want 全时段常驻分发命令被移除、分发只由技能命令承载, so that 只有一条分发路径，校验与重放保持简单。
18. As a 开发者, I want 规则版本提升且旧版本存档被显式拒绝, so that 不会出现混版本状态破坏重放确定性。
19. As a 开发者, I want 分发作为普通引擎命令与事件进入历史, so that 终局真诅咒分支的重放与调试覆盖诅咒路径。

## Implementation Decisions

- **技能窗口触发扩展**：fleur-cross 纳入亮等级可触发的技能集合；触发条件与 rank 1–9 完全一致（攻击或干涉伤害伴随亮出等级；技能伤害不触发技能窗口）。引擎内"fleur-cross 永不触发技能窗口"的旧设定按 2026-09-05 裁决作废。
- **技能命令承载分发**：审判者发动时在技能命令上携带两卡分配；校验语义沿用原分发命令（分配键须与待分发卡集合完全一致、收件人须存活且互不相同、仅审判者本人可发动、窗口内一次性），校验失败整条命令拒绝。放弃走既有放弃路径，等级记入已用技能。
- **旧入口删除**：全时段常驻的分发命令与其处理函数整体移除；分发成功复用既有私密事件（每卡一条），供应区随即清空；私密事件过滤与投影保密规则不变。
- **自分发语义维持现状**：引擎不禁止分给自己，客户端不提供自己作为收件人（维持既定语义，本次不对齐、不新增限制）。
- **投影**：待分发的两张卡 ID 仍仅对审判者可见（作为选择器数据源）；窗口挂起期间审判者的合法动作集为放弃 + 发动，其余玩家无动作；审判者的攻击动作在投影层过滤已受 3 点伤害的目标。
- **客户端**：技能窗口动作区内两步发动（发动按钮 → 展开带标注的选择器 → 确认弹窗 → 发送）；确认弹窗复用既有通用确认组件；移除常驻分发面板；亮等级中文文案沿用现有「审判者」映射。
- **规则版本 0.3 → 0.4 硬切**：旧版本存档加载时显式拒绝（同 0.2→0.3 先例）；受影响对局需重建。协议版本号不变（线上消息形态未变，仅合法动作/命令语义调整）；协议文档同步（移除旧命令、记录技能命令新载荷）。
- **文档同步**：规则语料新增 2026-09-05 产品方裁决条目；规则分支覆盖文档的分发相关行改写；词表已于会话中更新（诅咒卡、真诅咒、假诅咒、技能窗口）。

## Testing Decisions

- **好测试只测外部行为**：命令进、事件/状态出；投影按 viewer 断言可见性。不测内部函数结构。
- **接缝全部复用既有接缝，无新增**：
  1. **引擎命令层（主接缝）**：
     - 窗口触发：自选亮等级（第 1/2 点伤害）、第 3 点被迫亮等级、挡刀承伤被迫亮等级均开启唯一窗口；技能伤害不触发；发动或放弃后不再出现第二次窗口。
     - 发动成功：每卡一条私密分发事件、供应区清空、归属进入终局判定数据；无伤害、匕首持有者与行动阶段原样恢复、不开新干涉或新技能窗口。
     - 放弃：放弃事件落地、技能永久失去、诅咒留供应区；此后正常家族胜利照常结算、不触发任何诅咒判定。
     - 校验拒绝分支：分配键与待分发卡集合不符、重复收件人、未知或已捕获收件人、非审判者发动、重复发动。
     - **终局分支测试迁移**：现有"真诅咒独赢"等终局测试原先经旧分发命令驱动，旧命令删除后必须改由"亮等级 → 技能命令"新路径驱动，终局断言保持不变。
  2. **投影层**：审判者的攻击动作过滤已受 3 点伤害的目标；窗口期合法动作集（审判者为放弃 + 发动，其余玩家无动作）；分发完成后任何 viewer 的合法动作不再含分发或发动动作（唯一入口的回归断言）；待分发卡 ID 仅审判者可见；其余玩家与观众视图无诅咒泄露。
- **先例**：现有引擎命令测试、规则分支覆盖测试、投影测试与投影保密性质测试的既有模式。
- **golden 补强**：不止刷新版本戳——至少一份奇数局回放的命令流扩为"审判者亮等级 → 技能分发诅咒 → 打到终局"的完整路径，把诅咒分发纳入重放确定性回归；偶数局回放仅需版本戳刷新。
- **协议级 e2e**：新建诅咒流程 e2e 脚本（仿既有干涉 e2e 模式）：7 人局驱动审判者受伤亮等级、两步发动分发、打出真诅咒终局验证；全程以非审判者视角断言无泄露。
- **客户端人工验收清单**（无自动化 UI 测试基建，另有独立议题）：技能窗口横幅、两步发动展开、真假标注文案、确认弹窗文案与按钮禁用态、放弃后入口永久消失、攻击按钮 3 伤过滤、分发完成后无残留入口、其他玩家与观众视角无泄露。

## Out of Scope

- 多审判者对局（当前奇数局恒为 1 名审判者）。
- 审判者自分发的语义对齐（引擎允许、客户端排除，维持现状）。
- 审判者被捕获终局分支的胜负再裁定（维持现状；规则语料"独赢"与分支覆盖文档"平局"存在既有出入，另行处理）。
- 卡片式分发视觉升级（保持下拉框，后续可选）。
- 前端自动化测试基建。

## Further Notes

- 时机模型为产品方 2026-09-05 裁决：官方规则书原文未锚定分发时机，本模型出于平衡性（全程可发会退化成残局憋招稳赢）与全桌一致性（与其他技能同流程）选定，全程可发与开局窗口两个备选已被否决（见 ADR 0003）。
- 用户实测观察到的"给了一次刀之后仍显示可以用技能"即旧常驻入口所致；新模型下该入口不复存在。
- 上线影响：当前测试房间（0.3 版本）在部署后作废，需重建对局。
- 词表已同步：CONTEXT.md 新增真诅咒/假诅咒条目，改写诅咒卡与技能窗口条目。
