# check.py 增加废弃术语确定性检查

Type: task
Status: resolved
来源复盘: 2026-10-06 会话复盘（挡刀门控实施中「干涉窗口」5 处回归，落 4 个提交后才被 AI 评审抓到，返工 ce2486b）
裁决日期: 2026-10-06（范围/挂载点/词表三项经用户拍板）

## Problem Statement

（以下从维护者与玩家视角描述）CONTEXT.md 的 `_Avoid_` 废弃术语表只是文档约定，没有任何机械执行。废弃术语会反复混回用户可见文案、协议文档、测试名和代码注释——最近一次是「干涉窗口」（旧模型名，应为「干涉三段窗口」或具体窗口名）在 5 处回归，其中 3 处在前端源码、2 处在协议文档，落了 4 个提交之后才被 AI 评审发现，产生一轮评审返工。这不是孤例：术语返工在这个仓库已多次发生。而 `docs/agents/quality-checks.md` 自己承诺「出现明确且工具未覆盖的机械约束时，优先接入对应检查」——废弃术语恰是纯机械约束（固定词表、固定范围），本应由脚本在提交时拦下，而不是留给 AI 评审兜底。玩家侧的后果是：界面、帮助与协议文档里新旧两套领域语言并存（如「干涉窗口」vs「干涉请求/干涉投票」），学了一套术语仍看不懂全部流程。

## Solution

在既有守门脚本（本地 hooks 与远端 CI 共用的那一个）里新增一步「废弃术语」扫描：对固定范围的文件全文检索 v1 五词（干涉窗口、点名请求、伤害格、血条、座位色），任一命中即失败，逐条输出 `文件:行号`、命中的废弃术语及其规范替代名（如 废弃「干涉窗口」→ 规范「干涉三段窗口」）。范围覆盖用户可见文案面与承载领域语言的代码面：前端源码目录全部文本文件、协议文档、领域引擎包、服务端包、后端测试目录。挂载两点：pre-commit 只查本次暂存且在范围内的文件（不误伤工作区里未暂存的脏文件）；pre-push 与 CI 全量兜底。另提供独立子命令供人工随时排查全仓术语健康度。同步在自动检查文档中记载词表机制：CONTEXT.md `_Avoid_` 是术语权威，检查内嵌的是无歧义子集，新增 `_Avoid_` 词时按「零假阳性」标准人工收录。

## User Stories

1. As a 维护者, I want 提交里包含废弃术语时 pre-commit 立刻失败并指出文件与行号, so that 不等评审往返就当场改掉。
2. As a 维护者, I want 推送与 CI 对全量范围兜底扫描, so that 绕过本地 hooks 的提交也被拦下。
3. As a 实现代理, I want 失败信息直接给出规范替代名, so that 不用翻 CONTEXT.md 就能一次改对。
4. As a 实现代理, I want 「干涉三段窗口」这类规范写法不被误报, so that 正确的术语不被检查骚扰。
5. As a 评审代理, I want 术语匹配这类机械判断完全交给脚本, so that 我把评审注意力留给语义、规则解释与跨文件一致性。
6. As a 产品方, I want 界面、帮助与协议文档永不出现已废弃的旧模型术语, so that 玩家不被旧概念混淆。
7. As a 玩家, I want 全部界面始终用「干涉请求」「干涉投票」「线索槽」等现行叫法, so that 我学一套术语就能看懂整个流程。
8. As a 未来贡献者, I want 引擎与服务端代码注释里也不出现废弃术语, so that 我从代码学到的领域语言是现行的。
9. As a 维护者, I want pre-commit 只检查本次暂存且在范围内的文件, so that 工作区里无关的脏文件不会阻塞我的提交。
10. As a 维护者, I want 范围外的文件（如 ADR 历史引文、议题空间）不被扫描, so that 「引旧词以否定」的正当写法不被误伤。
11. As a 维护者, I want 一个独立子命令随时全量排查, so that 不用故意犯错也能查看当前术语健康度。
12. As a 维护者, I want 无法按 UTF-8 解码的文件被跳过而非报错, so that 检查在任意工作树状态下都能给出确定结论。
13. As a 维护者, I want 词表收录流程写进自动检查文档, so that 未来扩充 `_Avoid_` 词时不需要考古本次决策。
14. As a CI, I want 术语检查与既有检查共用同一脚本、同一退出码约定与同一 hooks 入口, so that Windows/Linux 双平台行为一致且无需重装 hooks。

## Implementation Decisions

- **词表 v1 五词及其规范替代名**（均出自 CONTEXT.md `_Avoid_`，按零假阳性标准筛选）：干涉窗口→干涉三段窗口；点名请求→干涉请求；伤害格→线索槽；血条→线索槽；座位色→真实阵营色。词表内嵌在检查脚本中并注释指回 CONTEXT.md，不自动解析 `_Avoid_`（其限定语如「单用」「仅用于文案」无法可靠机读）。
- **范围**（用户拍板「文案 + 全部 Python」）：前端源码目录全部文本文件、协议文档、领域引擎包、服务端包、后端测试目录。明确排除：领域术语文档本身（`_Avoid_` 定义所在）、docs 与 ADR（历史引文正当）、议题空间目录（讨论旧模型正当）。
- **纯函数接缝**：核心是「给定文件路径集与词表，返回违规列表（路径、行号、术语、替代名）」的纯函数；全量模式与暂存模式都复用它。检查在脚本进程内直接调用，不走子进程步骤。
- **挂载**：全量检查在完整验证入口的最前面（最便宜的检查先跑）；暂存模式复用 pre-commit 现有入口，用暂存文件列表过滤出范围内的现存文件（已删除的暂存路径跳过）。
- **CLI**：新增独立子命令（如 `terms`）执行全量扫描并打印结果，退出码语义与其它检查一致，供人工排查。
- **输出为简体中文**（仓库面向中文用户的约定），格式给出 文件:行号、废弃术语、规范替代名。
- **编码**：按 UTF-8 读取，解码失败的文件跳过（脚本的子进程环境已强制 PYTHONUTF8）。
- **文档同步**：自动检查文档增补一段——废弃术语由脚本负责，词表是 CONTEXT.md `_Avoid_` 的无歧义子集，扩充标准与流程。
- 已实测（2026-10-06）：五词在既定范围内零命中，检查落地即绿，不阻塞现状。

## Testing Decisions

- **只测外部行为**：违规列表的路径/行号/术语/替代名内容；干净文件返回空；范围外路径不报；「干涉三段窗口」包含规范词不误报（子串安全）；同一行多个术语全部列出；空文件与非 UTF-8 文件安全跳过；暂存列表中已删除的路径不报错。
- **接缝复用，零新增**：守门脚本的既有测试文件已经以模块导入方式直接测脚本函数，并以临时 git 仓库测 CLI 入口与 hooks 行为——新测试完全沿用这两个先例手法。
- **必须覆盖的 CLI 行为**：暂存模式在命中暂存文件时非零退出、命中仅存在于未暂存内容时不拦、独立子命令的退出码与输出；完整验证入口在术语命中时先于测试套件失败。
- 禁止 mock 被测函数本身；夹具用临时目录构造，不依赖真实仓库的当前内容（真实仓库「今天零命中」是验收证据，不是测试断言——CI 的完整验证本身就是那道全量回归锁）。

## Out of Scope

- 词表扩充候选：「干预」「事件类型」「解封」「挡刀」「标记/备注/标签」「active player」——各有假阳性或范围歧义（如「人工干预」日常用语、eventType 的中文解释、CONTEXT 引旧词以否定的写法），待真实误报案例出现再议。
- CONTEXT.md `_Avoid_` 的自动解析与自动词表同步。
- docs/、ADR、议题空间（.scratch）的扫描。
- 英文废弃术语与英文文案面。
- 评审代理提示词的改动（机械判断下沉脚本后，评审自然不再扫这类问题）。
