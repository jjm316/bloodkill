开路问题（你的示例）：刺客打了两点伤害之后，被打的人从亮一个标记到亮两个标记和数字——这时候被打的人还能放技能吗？
不能。引擎现状：技能造成的伤害不开任何窗口，且这两张牌都不是受害者自己选的。
  1. 技能伤害不开窗：engine.py:795-801 只认 trigger ∈ {attack, intervention} 才开技能窗；这与帮助文案「技能造成的伤害不产生新的干涉投票，也不会开出新的技能窗口」、规则书 skill.reveal-rank（因攻击伤害展示 rank 时才可发动）三处一致。
  2. 两张亮牌均无选择：第 1 点引擎直接亮 rank（若未亮），第 2 点自动亮剩下的一张标记——哪张由 Python 集合迭代序决定，实测随 PYTHONHASHSEED 翻转，是确定性缺陷（A1/A2）。规则书 damage.reveal 说 1–2 点应由玩家自选，只有感应者（rank 5）技能文本写明「通常强制其展示 rank」。
  3. 连锁后果（封印效应，A4）：受害者的 rank 被技能伤害抢先亮出后，其技能窗永远不会再开——之后受攻击伤害只能亮标记，rankRevealed 永假。唯一解药：另一名炼金治疗他退回 rank，再被攻击伤害亮出 rank 才重新开窗。规则书没写这条连锁，需要拍板是否有意保留。
  4. 边界：若受害者已 2 伤，这 2 点的第 2 点即第 4 点 → 立即捕获终局，终局按「active = 刺客」判定（捕到敌方领袖 → 刺客阵营胜；捕到非领袖 → 刺客阵营负，B13）。
「不能放技能」这一半是三方一致的共识（规则书 / 引擎 / 帮助文案）；「怎么亮牌」那一半是本页第一条要拍的 A1/A2。

耦合主线速览：一条伤害落地要穿过多少规则

伤害源
attack / skill / reaction / intervention→ 盾拦截判定
仅 attack·skill·reaction 源→ 伤害点循环
每点 +1 伤 + 亮 1 牌→ 亮牌权
自选窗 / 被迫 rank / 引擎自动→ 第 4 点？
捕获→终局分支→ 技能窗
仅 attack·intervention 且 rank 新亮→ 技能效果
又可能产生新伤害回到起点
几乎所有耦合点都挂在这条链的某个环节上：亮牌权（A 组）、盾/扇/剑的拦截（B 组）、窗口资格（C 组）、终局按「谁造成的」判（D 组）。
