# 测试工具箱：服务端进程陈旧告警

Status: resolved（2026-10-07 实施、验收并销案）

## Problem Statement

测试服务端是脱离终端的长跑 uvicorn 进程，改了后端代码（引擎、投影或服务层）后它**不会自动加载新代码**；而工具箱的 `up`/`serve` 只要探到 `/health` 就绪就「直接复用」旧进程。于是「改了代码 → 界面没变 → 怀疑代码有 bug → 排查一轮 → 发现是进程陈旧，要 restart」这个循环反复发生：2026-10-05 干涉门控会话里，改完投影没重启 8010 端口进程，浏览器一直显示旧文案，浪费了一整轮排查。此前靠记忆里的坑位清单提醒「记得重启」，但记忆够不到实施子代理，坑照踩。

## Solution

工具箱在两个「复用旧进程」的出口（`status` 子命令、`up`/`serve` 的直接复用分支）主动对比**磁盘上服务端代码的修改时刻**与**端口监听进程的创建时刻**：代码更新就在输出里打一行醒目中文警告，点名最新被修改的文件并给出可直接复制的 restart 命令。不自动重启、不改变任何子命令的退出码与既有行为；诊断自身失败时静默跳过（fail-open），告警永不阻断工具箱。

## User Stories

1. 作为测试工具箱的使用者，我希望 `status` 一眼告诉我运行中的服务端是否落后于磁盘上的代码，这样不用靠记忆判断要不要 restart。
2. 作为看不到主机记忆的实施子代理，我希望 `up`/`serve` 复用旧服务端时工具主动警告代码已更新，这样改完后端跑 `up` 不会把陈旧状态静默带进浏览器会话。
3. 作为排查「改了代码界面没变」的维护者，我希望警告点名最新被修改的文件，这样能立刻确认是哪个改动还没生效，而不是先怀疑自己的代码。
4. 作为测试工具箱的使用者，我希望警告里直接给出含当前端口的 restart 命令，这样补救动作零思考成本。
5. 作为跑长局 e2e 的验证者，我希望告警永不阻断 `status`/`up`/`serve`（诊断失败静默跳过、退出码不变），这样新增检查不降低工具箱可用性，也不会打断进行中的对局。
6. 作为工具箱维护者，我希望扫描范围同时覆盖服务层与引擎/投影两个包，这样改任何一层都会触发告警。
7. 作为工具箱维护者，我希望 `__pycache__` 产物不参与判定，这样进程启动时写入的字节码不会造成假阳性。
8. 作为代码没改动的普通使用者，我希望正常运行时输出与从前完全一致，这样告警不产生日常噪音。
9. 作为批量检查的执行方，我希望新增的判定逻辑测试进入默认 Python 测试套件，这样判定回归会被 `check.py` 拦住。
10. 作为双击 bat 的中文用户，我希望「测试工具箱-状态.bat」不做任何改动就自动带出告警，这样既有入口零迁移成本。

## Implementation Decisions

- **判定基准**：对服务层与引擎/投影两个包下的全部 `.py` 取最新 mtime，排除 `__pycache__` 目录。
- **进程时刻**：对 netstat 已查得的端口监听 PID，用 Win32_Process 的创建时间属性转 Unix 时间戳；复用工具箱既有的 PowerShell/CIM 调用惯用法，不引入新依赖。
- **判定规则**：代码最新 mtime 晚于进程创建时间加 2 秒容差即视为陈旧。
- **两个挂点**：`status` 的「服务端：运行中」行之后；`ensure_server` 的「直接复用」分支日志之后。
- **告警形态**：一行中文警告（最新修改文件的相对路径 + 含端口的 restart 命令）；退出码保持 0；查不到 PID 或进程查询失败时静默跳过。
- **明确不做**：不自动 restart（会打断进行中对局，先告警知情，自动重启跑顺后另立票据）；不启用 uvicorn 热重载（会在 e2e 验证中途重启服务端、打破独立长跑形态）。
- **改动边界**：仅测试工具箱脚本（约 40 行：扫描、进程时刻查询、判定组装三个小函数 + 两处挂点 + 顶部 docstring 补一行）；服务端、引擎、前端、协议零改动。

## Testing Decisions

- 好测试只测外部行为：判定逻辑做成纯函数（输入为文件的 mtime 集合与进程时刻，输出为「是否陈旧 + 点名文件」），用临时目录构造新旧文件与 `__pycache__` 干扰项断言结果；不测 PowerShell 调用本身——进程时刻查询保持薄、fail-open，由实机验收覆盖。
- 被测范围：新增的纯判定函数。工具箱此前无测试，本批为该脚本建立第一个测试缝，且刻意选在最高处（判定函数）而非穿透系统调用。
- Prior art：`tests/` 下现有 unittest 套件的临时目录构造风格；`check.py` 的 python-tests 步骤全量执行、禁止跳过，新测试自动进跑批。
- 实机验收（进验收票据，不进自动测试）：触碰投影文件的 mtime → `status` 出告警 → `restart` → `status` 恢复干净；杀掉服务端再 `status` 不报错。

## Out of Scope

- 自动重启与 `--auto-restart` 开关、uvicorn 热重载、文件监听守护。
- 前端构建陈旧（`up` 的 build 步骤已管理）与依赖安装陈旧（依赖变更要重装而非重启）。
- 服务端、引擎、投影、协议、前端任何行为变更。
- bat 双击壳与部署清单改动。
