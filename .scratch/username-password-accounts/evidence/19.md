## 行为与公共接口

- 新增 `server/admin_api.py`：服务 startup 时在**同一进程**打开只绑定 `127.0.0.1` 的微型 HTTP 管理监听（手写最小 HTTP/1.1，仅 GET、单请求、拒绝 body），shutdown 关闭；查询直接读运行中内存（`manager`/`accounts`/`conns` 同一批对象），含实时在线状态。公网 FastAPI 应用不注册任何管理路由。
- 存档目录新增 `admin/` 子目录：`installation.json`（稳定安装标识 + 存档目录规范绝对路径 + 本次管理端口，服务每次启动写回；原子替换写入）与 `admin-token`（独立管理凭证，首次生成后同目录重启复用；Linux chmod 600，Windows 依赖目录 ACL）。服务端按启动时缓存的凭证 constant-time 校验，改动凭证文件需重启生效。
- 新增 `server/admin.py` CLI：`python -m server.admin users|rooms [--saves-dir DIR] [--port N]`，存档目录默认 `BLOOD_BOUND_SAVES_DIR` 或 `./saves`（与服务相同解析）。流程：读本地安装记录与凭证 → 请求 `http://127.0.0.1:<port>/admin/instance` 核对安装标识与存档目录（不符即拒绝，防误连另一实例）→ 携带 `X-Admin-Token` 请求 `/admin/users` 或 `/admin/rooms` → 中文渲染。CLI 不 import `server.app`，不打开存档/账号库；直连回环（显式 `ProxyHandler({})` 绕过系统代理）且禁止跟随重定向（自定义 handler 拒绝 3xx，凭证不转发）。
- 查询响应为允许字段（allowlist）：users = `username`/`accountId`/`roomCode`（当前未结束房间占用）；rooms = `code`/`gameId`/`status`/`locked`/`hostUsername`/`players[].username,online`。不序列化数据库行、房间 meta 或引擎状态，密码摘要/会话/hostToken 不进入输出。
- `server/accounts.py` 新增 `AccountStore.list_accounts()`（按用户名序全量只读）；`server/app.py` startup/shutdown 接线管理监听；`server/README.md` 新增「服务器管理命令（本机终端）」小节。

20/21 扩展点（已预留、未过度设计）：管理凭证/安装核对流程与 allowlist 行构建集中在 `AdminInstallation`/`AdminEndpoint`/CLI 请求管线，reset-password 与 close-room 增加端点时直接复用同一鉴权、防误连与中文报错路径；`room_rows()` 即 close-room 预览的数据源。

## 权限边界说明（V13.02「非本机来源」）

管理监听只 `bind 127.0.0.1`（`server/admin_api.py` 的 `start_admin_server` 固定 `host="127.0.0.1"`），非本机来源在 TCP 层不可达；公网入口无管理路由已由真实 HTTP 验证（伪造转发头 + 正确凭证均 404）。伪造代理头不能放开权限：管理端点不读任何转发头，唯一授权依据是仅存于服务器存档目录的独立管理凭证。Windows 本机无法伪造非 loopback 源地址，「外网 TCP 不可达」由绑定地址保证，未做真实外网连接探测（记录为环境边界，非行为缺口）。
