环境：Windows、工作树独立 `.venv`（Python 3.11）、Node 24、vitest 3 + React Testing Library（jsdom）。本工单为纯前端改动：未改服务端、未动生产环境（47.111.11.55）、未部署、未 push；所有账号均为 fixture 测试账号。

## 行为与公开接口

- 存储键加入稳定账号引用命名空间：`bloodbound:account:<accountId>:no-block`、`bloodbound:account:<accountId>:no-assist`（挡刀偏好，账号+设备作用域）、`bloodbound:account:<accountId>:event-log-filter`（日志筛选，账号+设备作用域，跨房间/对局保留语义不变）、`bloodbound:account:<accountId>:memo:<roomCode>:<gameId>`（备忘，账号+房间+对局作用域，ADR 0004）。
- 旧的无账号全局键（`bloodbound:no-block`、`bloodbound:no-assist`、`bloodbound:event-log-filter`、`bloodbound:memo:<room>:<game>`）不读取、不迁移、不清除：新账号一律默认状态（V12.03）。
- 备忘换局清理只删**当前账号**同房间旧局键；其他账号（含此前活跃账号）的键不受影响。
- `useIntervention`/`useMemoMarkers`/`EventLog` 接口加入 `accountId`；`GameScreen` 从 `credentials.accountId` 传入。App 层以 accountId 为 key 重挂载（工单 14 提供），各 hook 在 accountId 变化时同步重读偏好并清空自动代发去重键（防御性身份边界）。
- 账号退出后本地数据不清除：按「不自动导入」语义，残留数据因键位隔离永不进入下一账号，回到原账号仍可用自己的（设计取向见工单 Answer）。
- 无服务端改动、无协议改动：备忘不进协议（ADR 0004）；偏好只是本地开关，自动代发与手动点击同一 send 路径，wire 帧逐字节相同。
