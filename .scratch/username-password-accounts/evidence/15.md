## 行为与公开接口

- `POST /api/auth/password`（同源 Origin 校验，与其他 auth POST 一致）接收 JSON `{oldPassword, newPassword, confirmPassword}`：验证旧密码后设置新密码（6–12 原字符、确认完全相同，复用注册校验）。成功返回 200 `{account}`（仅公开账号对象，`Cache-Control: no-store`，不回显任何密码，不改当前 Cookie）；**当前登录保留原固定 30 天到期点**；同账号**其他设备的全部登录在同一事务内撤销**，其已建立的房间 WS 被主动停止：连接先移出注册表，再收 `auth.password-changed`「密码已修改，请重新登录。」中文终止帧并关闭，因此不能再发送动作、收不到后续私有投影；当前设备的连接（含同 token 多标签）不在撤销集，照常收发。座位、房主归属与占用不变。
- 失败分支：旧密码错 400 `auth.wrong-old-password`（「旧密码不正确，请重新输入。」）、新密码 5/13 字符 400 `auth.invalid-password`（含「6–12」）、确认不一致 400 `auth.password-mismatch`、非对象/坏 JSON 400 `auth.invalid-input`、无会话或已失效凭证 401 `auth.login-required`、跨站 Origin 403 `auth.invalid-origin`、存储失败 503 `auth.service-unavailable`。任何失败都不改原密码、不动任何会话（单一 sqlite 事务回滚）。
- 公开存储接口 `AccountStore.change_password(token, old, new, confirmation) -> (Account, set[被撤销 token 摘要])`：撤销集供服务层精确匹配连接（不把过期/接管连接误算入）。`Conn` 内存的 token 只在服务进程内哈希比对，不进日志/投影/URL。
- 前端：大厅/房间/回放共用的「当前账号」行新增「修改密码」按钮（退出登录左侧），展开 `PasswordChangeForm`（旧密码/新密码/确认新密码，`current-password`/`new-password` 自动填充属性，回车提交，提交中禁用+同步防重复「正在修改……」，失败 `role=alert` 中文反馈并保留输入可纠正，取消不发请求）；成功收起表单并显示「密码已修改，其他设备需要用新密码重新登录。」状态，本机保持登录不回登录页，重新打开表单密码已清空。密码只存在组件状态，成功/取消随卸载丢弃，不写 URL/localStorage。`GameScreen` 对 `auth.password-changed` 终止帧显示「登录已失效」横幅与「重新登录」入口（`useSocket` 对全部 `auth.*` 停止自动重连，14 已有）。
- 管理重置撤销全部登录属工单 20，本项未实现。
