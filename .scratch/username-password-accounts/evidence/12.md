## 行为与公共接口

- `RoomManager.join_or_resume(Room, Account)` 新人分支在占用检查中新增**跨房限制**：账号在其他未结束房间已有座位 → `RuleError("account.room-occupied", "你已有未结束房间，请返回原房间。", roomCode=…)`，与创建路径（09）同码同义；本人恢复原房优先判断，不算新占用。被拒时目标房 `playerCount` 不变、`/api/account/room` 不变。
- `RoomManager` 新增 `threading.Lock` 占用锁：`create_room` 与 `join_or_resume` 的「占用检查 → 座位提交 → 持久化登记」为原子步骤。创建与加入共用同一锁与同一检查语义，不同入口不能互相绕过。
- `server/PROTOCOL.md`：WS 新人加入分支补 `account.room-occupied`（details.roomCode 提供恢复目标）与「一账号一个未结束占用、并发最终唯一、正常终局释放全员」的协议说明。
- 前端 `GameScreen`/`App`：占用拒绝帧带 `details.roomCode` 时失败页直接提供「返回房间 XXXXXX」按钮（`onReturnToRoom` 以当前账号 player 模式重进原房），与大厅「返回房间」入口一致；无 roomCode 时保持返回大厅再查询。

## V06.01｜真实并发请求（独立客户端 + 可控同步点）

命令：`.venv/Scripts/python.exe -m unittest tests.test_account_occupancy -v`
用例：`test_v06_01_concurrent_create_from_two_sessions_collapses_to_one_room`、`test_v06_01_concurrent_join_of_two_rooms_yields_single_occupancy`、`test_v06_01_concurrent_create_and_join_mixed_race_leaves_single_occupancy`。
准备/输入：同账号两个独立会话 Cookie（注册 + 重新登录）；`ThreadPoolExecutor` 两/多线程在 `Barrier` 会合后同时发起真实 HTTP POST `/api/rooms` 或真实 WS hello（不同房号），请求并发到达真实 uvicorn。
预期：每组竞争最终最多一个有效未结束占用；成功/失败结果明确（不以此前无异常为通过）。
实际：并发建两组会话全部 200 且同一 roomCode、playerCount=1、两会话 `/api/account/room` 指向同一房；并发加入两房恰一个 state、另一个 error `account.room-occupied` 且 `details.roomCode`=成功房，失败房 playerCount=1，失败方按引导恢复原房得到同一 yourPlayerId；混合竞争按先到者占用，失败方得到原房引导。退出 0。
