## 要交付的行为

大厅显示自己的当前房间；已有占用时创建或加入别的房间会被解释并引导返回，多个设备同时请求也不能占两个房间。

## 前置依赖

[10 按账号加入房间及跨设备恢复座位](10-join-and-resume-account-seat.md)

## 验收条件

- [ ] 限制在服务端、所有设备与重启恢复中一致执行，失败不会残留新房或座位。
- [ ] 正常终局释放全员占用，玩家能进入下一房间；进行中离线仍保留占用。
- [ ] 返回当前房间保留原座位及房主身份，不能靠不同入口绕过限制。

## 测试与验证

- [ ] **V06.01｜真实并发请求**：同账号并发建两个房、加入两个房、建房与进房混合竞争，每组最多产生一个有效未结束占用。
- [ ] **V06.02｜跨设备/失败**：两个独立会话分别请求新房，失败方获得当前房入口；拒绝后重启仍无第二个房或幽灵座位。
- [ ] **V06.03｜状态转换**：进行中断线、退出到大厅仍不能进别房；正常终局后可以建房/加入且所有玩家占用解除。
- [ ] **V06.04｜前端行为**：限制来自服务确认，直接 API 或 WS 请求不会成功，即使按钮或客户端状态被绕过。
