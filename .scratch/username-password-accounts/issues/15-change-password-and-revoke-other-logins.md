## 要交付的行为

玩家在界面验证旧密码并设置新密码，当前设备继续使用，其他设备退出并用新密码重新登录。

- [x] 账号归属、房主及座位保持，不出现修改密码成功但实际未更新的提示。

## Answer

已实现主动改密并撤销其他设备登录：`POST /api/auth/password` 验证旧密码后设置新密码（6–12 字符、确认一致、中文反馈），成功时**当前登录保留原固定 30 天有效期**、同账号其他设备登录在同一事务内全部撤销并停止其已建立的房间 WS（`auth.password-changed` 中文终止帧后关闭，后续动作失败、私有帧停止；当前设备连接照常操作），旧密码不能再登录、新密码重登恢复原座位/房主且不改占用归属；任何校验或存储失败都不改变原密码与会话（真实只读数据库注入 503，恢复后重试与返回一致）；密码不进日志、URL 或本地存储。真实 uvicorn/HTTP/WS 验证（边界、已建 WS 撤销、重启、失败注入）见 [15 验收证据](../evidence/15.md)；前端大厅/房间共用「修改密码」表单组件测试覆盖回车提交、防重复、中文错误与成功提示。浏览器改密 UI 真实操作流（界面改密、其他设备被踢后的重新登录路径）已于 2026-10-16 由第二批验收子 agent 外部 Chrome 真实执行通过（见证据「外部 Chrome 浏览器验收」节）。全量 `scripts/check.py` 通过（331 Python、239 前端、TypeScript 与生产构建）。
