## 要交付的行为

玩家输入房号加入，在其他设备重新登录相同账号后回到原座位；锁房或开局后仍能恢复，其他人不能按同名冒领。

## Answer

分支 `codex/account-10`，实现与测试见提交 `feat(rooms): join by room code with account-bound seat recovery`。

- `RoomManager.join_or_resume` 把**本人恢复与新人加入分开判断**：已有座位的账号在锁定、开局甚至已结束房间都能恢复原座位（已结束房间保留终局浏览），房主恢复管理权；新人仅能进入未锁定的等待房间，满 12 人前拒绝新增（`room.full`）。锁定/开局/满员/结束分别给出中文原因（`room.locked` / `room.already-started` / `room.full` / `room.ended`），被拒连接不产生座位、占用或重连；`server/PROTOCOL.md` 已同步。
- 修复握手边界：hello 完成前的连接不再收到按空视角生成的投影广播（`Conn.ready`），跨设备恢复时不会闪现旁观帧。
- 前端（`client/src/useSocket.ts`、`GameScreen.tsx`）：加入阶段收到任何房间错误帧即停止初始重连并显示中文原因，保留返回大厅入口；新增满员/结束/占用文案；接管横幅改为账号语义「已在其他设备进入房间」。`Lobby` 六位房号加入流程有行为测试。
- 证据与验证记录见 [../evidence/10.md](../evidence/10.md)：V04.01–V04.04 全部以真实 uvicorn/HTTP/WS（独立临时存档与端口）执行，V04.04 用 6 人与 7 人对局真实停止进程树后以同存档目录重启验证归属与身份不漂移；界面部分（失败页回大厅等）留给主 agent 外部 Chrome 验收。
