## 要交付的行为

无玩家占用的已登录用户能旁观公开对局；已占座的账号不能同时旁观，旁观中的账号成为玩家后旧旁观连接停止。

[12 一人一个未结束房间及并发占用限制](12-one-active-room-and-races.md)

## 验收条件

- [x] 旁观没有游戏/房主管理权限，只接收公开事实；未登录旁观被拒绝。
- [x] 玩家与旁观互斥覆盖直接请求、不同设备和先旁观后进房的顺序。
- [x] 被限制时能返回自己的房间；已结束回放仍可独立访问。

- [x] **V10.01｜真实 WS/投影**：已登录旁观者收到已知局的公开视图，不能取得其他玩家的隐藏身份、私有诅咒结果或私有事件。
- [x] **V10.02｜授权反例**：匿名、无效会话、旁观者发玩家命令或房主管理命令，均被拒绝且对局状态不变。

## Answer

分支 `codex/account-16`，实现与测试见提交 `feat(server): exclude seated accounts from spectating and stop stale spectator conns`。

- WS hello `mode="spectator"` 增加服务端校验：账号在任何未结束房间持有玩家座位 → `spectator.seat-held`（中文原因 + `details.roomCode` 返回原房入口），跨设备一致（按账号占用判断，第二会话同样被拒）；被拒不产生座位、房态不变。结束房拒绝实时旁观（`room.ended` 旁观语境文案指向回放），23 的 REST 公开回放入口不受影响。
- 成为玩家即停止旧旁观连接：hello player 占座（加入/恢复）与 REST 建房占座后，`_stop_account_spectators` 终止该账号全部已建立旁观连接（`spectator.became-player` 错误帧后关闭，不再收帧、动作不可达）；仍在握手中的连接由其后的 hello 校验自然落入互斥拒绝，任何交错都不出现「玩家占用 + 活动旁观」。同房其他账号旁观连接不受影响。
- V10.01 以真实完整局（smoke 48–49 条命令）全程收集旁观流：只有公开投影/事件，终局前帧不含任何完整身份绑定（终局揭晓的 6 个身份对做已知私有事实对照）与私有字段；亮牌事件的公开标记值按规则允许。V10.04 用独立会话 + Barrier 真实并发，两种交错断言最终归属唯一、旁观必不活动，复跑 5 次稳定。
- 前端：互斥拒绝直接提供「返回房间 XXXXXX」；「旁观已停止」终止页且不再自动重连（`spectator.*` 终止性错误）；旁观模式结束房文案与回放引导一致；大厅已有房间时禁用「旁观」并给中文说明。
- 证据与验证记录见 [../evidence/16.md](../evidence/16.md)：V10.01–V10.05 全部以真实 uvicorn/HTTP/WS 执行；浏览器旁观 UI 流已于 2026-10-16 由第二批验收子 agent 外部 Chrome 真实执行通过（已在证据中登记）。
