## Answer

分支 `codex/account-20`，实现与测试见提交 `feat(accounts): reset password via admin CLI and revoke all logins`（`311fcb8`）。

- **CLI（`server/admin.py`）**：`python -m server.admin reset-password 用户名` 先走 19 的防误连核对（安装标识 + 存档目录），通过后交互隐藏输入新密码与确认密码——真实终端走 `getpass`（Windows 控制台经 msvcrt 逐字符读取、不回显，已用 CreateProcess + WriteConsoleInput 在真实控制台实测），stdin 为管道/重定向时逐行读取，等价安全语义：密码不进命令行参数、不回显、不写入输出或日志。校验 6–12 字符且两次一致，中文报错可重试；直接回车、输入流结束或 Ctrl-C 按取消处理，非零退出且不修改任何账号。不提供 `--password` 类参数，多余位置参数被 argparse 拒绝。
- **服务端（`server/admin_api.py`）**：新增仅限本机回环的 `POST /admin/reset-password`，复用 19 的管理凭证 constant-time 校验与中文报错；用户名不存在返回 404 明确报错、不自动创建账号；非 POST、格式错误、密码越界分别 405/400 拒绝；持久化/撤销失败返回 500「重置未完成」不报成功。`server/accounts.py` 新增 `AccountStore.reset_password`：更新 salt+hash 并撤销该账号全部未撤销会话，**同一事务**提交。
- **撤销与约束**：撤销后由 `server/app.py` 的 `_stop_account_connections` 停止该账号全部已建立房间 WS（复用 14 的 `auth.session-revoked` 终止管线：中文说明帧后关闭、旧连接不能再发合法动作、收不到后续私有投影）；座位与房主归属不变，用新密码重新登录可恢复原座位；其他账号的登录与连接不受影响。公网应用无管理路由，普通账号/房主/外网请求拿不到管理权限（写路径负面断言）。
- 证据与验证记录见 [../evidence/20.md](../evidence/20.md)：V14.01–V14.05 全部以真实 uvicorn 子进程 + 真实 CLI 子进程（stdin 管道喂入密码）+ 真实 WS 客户端在独立临时目录与端口执行。全量 `scripts/check.py` 退出 0（Python 329 项、前端 vitest 通过）。
