## Answer

分支 `codex/account-21`，实现与测试见提交 `feat(admin): confirm, back up and close a single room via CLI`。证据与验证记录见 [../evidence/21.md](../evidence/21.md)。

- **确认管线（防误处理）**：`python -m server.admin close-room 房间号` 经 19 的防误连核对后，先 `GET /admin/close-room/preview?code=…` 显示该房当前信息（房号/对局/状态/锁定/房主/玩家在线），要求**再次输入同一房号**确认；输入其他内容或回车即「已取消」非零退出。确认提交携带预览记下的对局引用与修订号（`expectedGameId`/`expectedRevision`），预览后目标变化（有人开局、行动或房号被新房复用）一律 409 `admin.target-changed` 拒绝；不存在 404、已正常结束/已关闭 409，均有中文报错与非零退出，且不影响相邻房间。
- **先备份后关闭**：`RoomManager.admin_close`（`server/rooms.py`）在占用锁内先把该房 `game.json.gz`、`meta.json`（含座位归属）与 `closure.json`（关闭事实）原子写入存档目录下隔离的 `admin-backup/<gameId>/`，任何一步失败 → 503「备份失败…房间未关闭，保持可用」；随后才移出活动存档、置 `status="closed"`、清空决策窗口、移出活跃注册表（即释放全部占用）。移出活动存档失败 →「备份已完成，但移出活动存档失败…关闭未完成」503，房间保持可用，重试整目录重写同一备份。
- **停止与通知**：`apply_command`/`set_locked` 对 closed 房直接拒绝（含调度器迟到的超时代发，活动存档不会被重建）；WS 循环对关闭竞态窗口里的迟到消息先终止连接；app 层执行器清空窗口后走既有 `DeadlineScheduler.sync` 取消计时器，再以 19 的 `_terminate_conn` 管线向该房全部连接发送 `room.admin-closed` 中文终止帧并断开。其他房间照常（V15.02 对照断言）。
- **关闭不是正常终局**：备份可 `load_game` 读回、`ReplayPlayer` 逐帧重放到关闭那一刻的修订号，全程 `status != "ended"`、无 `result`、非终局帧无 `identity`（V15.05）；被关房 404、不能重进、回放 404（落在 23 的 `status != "ended"` 拒绝路径之外的房间不存在路径）；真实重启（taskkill + 同目录重启）不恢复该房、不重新占用、备份与关闭记录原样，重复处理明确报告「已于 … 被管理关闭」并附备份路径。没有房主解散按钮（房主动作仍只有开局/锁定）。
- **前端**：`useSocket` 把 `room.admin-closed` 列为终止帧（停止重连），`GameScreen` 显示「房间已被管理员关闭」横幅（说明不产生胜负或身份揭晓）与「返回大厅」入口；vitest 覆盖等待/进行两种状态。
- 22（关闭房的恢复与故障）与 24/27（文档化）在此管线之上继续；CLI 实际用法已更新进 `server/README.md`。
