## 要交付的行为

玩家登录后创建六位房间，立即看到自己的座位和房主标记；房主可以使用现有开始、锁定、解锁操作。

## 前置依赖

[08 已有账号登录与持续显示当前身份](08-login-and-current-account.md)

## 验收条件

- [ ] 创建行为建立房主账号及自身座位归属，页面持续显示用户名和房号。
- [ ] API 和房主操作均以登录账号授权，姓名或旧房主令牌不能取得权限。
- [ ] 创建失败可重试，不残留一个无法返回的半创建房间；既有规则和管理能力保持。

## 测试与验证

- [ ] **V03.01｜真实 API/WS**：登录创建后收到自己的座位、房主标记和可用管理操作；另一已登录账号不能开始或锁定该房。
- [ ] **V03.02｜授权反例**：无登录、无效会话、伪造用户名、旧房主令牌分别尝试创建和管理，均无成功状态变更。
- [ ] **V03.03｜持久化**：创建后重启服务，同一账号仍是原房主，返回页面不新建另一个座位。
- [ ] **V03.04｜失败注入/前端**：创建请求失败、重复点击及回复丢失时界面给出恢复入口；检查已存在的房间归属与页面不会互相矛盾。
