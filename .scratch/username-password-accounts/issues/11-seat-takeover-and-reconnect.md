## 要交付的行为

同账号在手机或新标签页进入同一座位时，新连接接管；旧页面明确提示已在别处进入，并停止操作和自动重连。

- [x] 普通网络断线仍按既有机制重连，接管与一般断线的提示和恢复路径可区分。

## Answer

分支 `codex/account-11`，实现与测试见提交 `feat(rooms): new connection takes over seat and old one stops racing`。

- **服务端接管语义补齐**：`Conn` 新增 `taken_over` 标志——旧连接被 pop 出连接表后，其循环在关闭竞态窗口里取到的迟到命令或房主操作一律收到 `seat.taken-over` 中文拒绝（命令拒绝仍带 ack，客户端发件箱不卡死），引擎状态不变。既有语义保持：同一座位只允许一个活动玩家连接，新连接接管后旧连接收到 `taken-over` 帧并被关闭，不再收到任何投影、事件或私有帧；接管不撤销旧设备的账号登录（会话仍有效，占用仍指向原房，可返回大厅再进入）。`server/PROTOCOL.md` 已同步接管边界与错误码。
- **前端终止路径**（`client/src/useSocket.ts`）：`taken-over` 为终止性事件——丢弃待确认命令队列（旧连接没有资格补发）、`send`/`sendHost` 停止入队与发送、旧 socket 的迟到 state/event/ack 帧一律忽略（不污染接管后的状态）、不再调度重连；普通断线不受影响，保留指数退避重连与待确认命令经新连接补发。接管横幅沿用「已在其他设备进入房间」。
- 证据与验证记录见 [../evidence/11.md](../evidence/11.md)：V05.01/V05.02/V05.04 全部以真实 uvicorn/HTTP/WS（独立临时存档目录与动态回环端口、三独立登录会话模拟多设备）执行，覆盖「被接管旧连接再试原本合法动作」与「保留的合法连接（不同账号对照座位）仍能操作」双向断言；V05.03 前端受控时间测试覆盖接管不重连、普通断线重连恢复的对照。浏览器双设备界面验收清单已列出，留给主 agent 外部 Chrome 执行。
