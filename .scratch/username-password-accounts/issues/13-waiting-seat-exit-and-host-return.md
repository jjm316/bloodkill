## 要交付的行为

普通等待玩家主动退出后让出座位并可换房；房主返回大厅保留座位和身份，对局中的离开则只断开连接。

## 前置依赖

[12 一人一个未结束房间及并发占用限制](12-one-active-room-and-races.md)

## 验收条件

- [ ] 等待普通玩家退出更新全员名册、释放占用，后续加入使用新的玩家引用。
- [ ] 退座持久化且事件重放一致，座位顺序与实际玩家集合可正确开局。
- [ ] 房主返回、普通临时断线/退出登录和进行中返回不会被当作退座；不增加解散或转让。

## 测试与验证

- [ ] **V07.01｜真实 API/WS/前端**：普通等待玩家主动退出，全员名册更新后该账号能进入另一房；房主页面显示返回大厅而非退座。
- [ ] **V07.02｜事件/持久化**：加入→退出→重加→重启→重放，对比名册、玩家引用和顺序，不能残留已退出玩家或重复座位。
- [ ] **V07.03｜开局边界**：退出后人数为 5 时不能开始，补齐至 6 时可开始；6/7/12 人包含退出重加时规则初始化仍一致。
- [ ] **V07.04｜竞争/反例**：退出与开局同时竞争，最终只有一种合法状态：成功退座后不在局中，或已开局拒绝退座且保留占用。
- [ ] **V07.05｜身份分支**：等待房主返回、普通断线/刷新/退出登录、进行中离开均可恢复原座位且占用仍存在。
