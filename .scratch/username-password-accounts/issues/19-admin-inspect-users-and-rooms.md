## Answer

分支 `codex/account-19`，实现与测试见提交 `feat(admin): inspect accounts and rooms via loopback admin CLI`（`ea8c238`）。

- **运行时行为（不另建实例）**：服务 startup 时在**同一进程**打开只绑定 `127.0.0.1` 的管理监听（`server/admin_api.py`，手写最小 HTTP/1.1，仅 GET），查询直接读运行中内存状态（含实时在线连接）；`server/admin.py` CLI 通过它查询，不 import `server.app`、不打开存档或账号库。公网应用不注册任何管理路由。
- **管理凭证与防误连**：独立凭证与实例记录在存档目录 `admin/` 子目录（`admin-token` 服务启动生成并缓存校验、`installation.json` 记录稳定安装标识 + 存档目录规范路径 + 本次管理端口）。CLI 请求 `X-Admin-Token` 直连回环（绕过系统代理、拒绝重定向转发凭证），并先核对 `/admin/instance` 的安装标识与存档目录——端口指向另一实例时中文报错拒绝，不误操作；同一台机器的第二实例经真实双服务验证互不影响。
- **输出**：`users` 输出用户名、稳定账号引用（accountId）、当前未结束房间占用；`rooms` 输出房号、对局引用、状态（等待中/进行中/已结束）、锁定、房主、玩家在线情况。响应为允许字段（allowlist），密码摘要、会话、hostToken 与管理凭证不进入任何输出；服务未运行/配置缺失/凭证错误均有中文报错与非零退出。
- **20/21 扩展点**：鉴权、安装核对、中文报错与 `room_rows()` 预览数据集中在 `AdminInstallation`/`AdminEndpoint`/CLI 请求管线，reset-password 与 close-room 增加端点即可复用，未做多余预建。
- 证据与验证记录见 [../evidence/19.md](../evidence/19.md)：V13.01–V13.04 全部以真实 uvicorn 子进程 + 真实 CLI 子进程（`python -m server.admin users/rooms`）在独立临时目录与端口执行；已结束房间用真实完整对局（49 条命令）制造。全量 `scripts/check.py` 退出 0（Python 294 项、前端 213 项通过）。
